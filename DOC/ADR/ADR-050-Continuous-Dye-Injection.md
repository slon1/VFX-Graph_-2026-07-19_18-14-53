## ADR-050: Продолжительный впрыск dye вдоль жеста (F3.1)

**Статус:** Принято владельцем 2026-10-21. EditMode зелёный, visual проверен и принят.
**Дата:** 2026-10-20
**Контекст:** M3D Framework, после F3.0 ([ADR-029](ADR-029-Cross-Resolution-Dye.md)). Ветка `feature/reynolds-boids`, трек stable-fluid.
**План:** [`plan-stable-fluid.md`](../plan-stable-fluid.md) §4, строка F3.1
**ТЗ:** [`todo-F3.1.md`](../last/todo-F3.1.md)
**Не меняет в этом ADR:** кернелы F1 (Divergence/Jacobi/ZeroMean/Subtract/SolidWall); кернелы F2 (VorticityConfinement/CopyScalar/MacCormackCombine); `AdvectScalarPass`, `AdvectVelocityFieldPass`, `SeedScalarDiskPass`, `TouchInjectVelocityFieldPass`, `TouchInjectGrayScottPass`; валидаторы; `Fluid2D.asset`, `Fluid2D_HarrisOrder.asset`, `Fluid2D_Vorticity.asset`, `Fluid2D_MacCormackDye.asset`, `Fluid2D_HighResDye.asset`.

### Решения владельца (2026-10-20)

1. Закон смешивания — **аддитивный** (не `max`). Следствие и оговорка: §2.
2. Красить **всегда, пока есть touch** (без gate по движению).
3. Жирный сид заменяется на **тонкий**, сид остаётся в цепочке: `SeedScalarDiskPass`, `RadiusUV = 0.04`.
4. Ширина штриха = `touch.radius × radiusScale`, `radiusScale = 1`. Ширина зависит от `touchRadius` в `InputRouter`.
5. Затухание краски нужно; как параметризовать — §3a.

### Контекст

F3.0 ([play-F3.0-touch.md](../last/play-F3.0-touch.md)) показала: dye 512² при velocity 128² резче, чем 128²/128², и **тонкий след жеста на 512² выживает** (ножка гриба читается нитью). Но источник dye в `Fluid2D*.asset` — одноразовый `SeedScalarDiskPass` (`radiusUV=0.16`, диск ≈ 5.1 мировых единицы при `Size=32`). Он и рисует макро-гриб ([Techdebt 8n](../last/Techdebt.md)): velocity-жест лишь деформирует уже существующий жирный диск. Нить на ножке — побочный след, а не результат целенаправленной подачи краски.

Гипотеза F3.1: если dye **подаётся вдоль самого жеста** тонким штрихом (кисть той же ширины, что кисть velocity), а сид сжат до размера кисти, то нить становится основным элементом картинки. Это «аналог `TouchInjectVelocity` в `dye`» из [`plan-stable-fluid.md`](../plan-stable-fluid.md) F3.1.

Что уже есть в коде (проверено чтением, 2026-10-20):

- `InputRouter` пишет `TouchForce { pos, delta, radius, strength }` каждый кадр (`Touch.hlsl`). Дефолты `touchRadius = 1`, `touchStrength = 10` (в сценах `Physarum.unity` и `Boids_Fluid2d_test.unity` те же значения; `Test1.unity` в репозитории нет — проверено Шагом 0). Скриптованный жест F2.3 — `ScriptedTouchStroke` через тот же `InputRouter.Sample`.
- `TouchInjectVelocityFieldPass` кладёт `delta * falloff * strength` в velocity. `TouchInjectGrayScottPass` — `max`-вброс в скаляр `V`. Готового пасса «touch → один скаляр» нет.
- Кисть при `touchRadius = 1`: тексель velocity 128² = 0.25 ед. (кисть ≈ 4 текселя), тексель dye 512² = 0.0625 ед. (≈ 16 текселей).
- `dt` в пассы приходит как `Time.deltaTime × SimulationSpeed`, без clamp ([`SimulationWorld.cs`](../../Assets/Scripts/Runtime/SimulationWorld.cs), F0.7 не сделан).
- Затухание скаляра уже реализовано в `AdvectScalarPass.DissipationRate`: `dye ← sample(...) · exp(−rate·dt)`, внутри кернела адвекции (§3a).

### Решение

#### 1. Новый пасс — `TouchInjectScalarFieldPass` (generic, не «Dye»)

Имя по технике ([ADR-026 §«Конвенция имён»](ADR-026-F2-Small-Scale-Structure.md)); `fieldName` по умолчанию `"dye"`.

- `TouchInjectScalarFieldPass : FieldKernelPass`, `DisplayName` «Touch Inject Scalar Field», `Category = PassCategory.Emit`, `KernelName = "TouchInjectScalar"`.
- `FieldWrites`: одно поле `fieldName`, `FieldAccess.WriteInPlace`, `FieldSemantic.Scalar`, 1 канал. `FieldReads` пусты. `RequiresSquareTexel` не переопределять.
- Параметры (`[SerializeField]`, push каждый кадр — live-tweak в Play):
  - `injectRate` (1/с, `Min(0)`, дефолт `60`) — скорость набора краски под центром кисти; постоянная времени `1/injectRate`;
  - `maxValue` (`Min(0)`, дефолт `1`) — потолок насыщения; совпадает со `SeedScalarDiskPass.Value`, `colorScale` квада сопоставим;
  - `radiusScale` (`Min(0.01)`, дефолт `1`) — множитель к `touch.radius`.
- Диспатч по разрешению write-поля (`dye` 512²).

#### 2. Закон впрыска: аддитивный с мягким насыщением

Для каждого текселя `p` (мировая позиция на плоскости поля, как в `TouchInjectGrayScott`):

```hlsl
// суммарный вес кисти по всем touch; для каждого — отрезок [pos − delta, pos]
float s = 0;
for (t) {
    float3 a  = touch.pos - touch.delta;
    float3 ab = touch.delta;
    float  u  = saturate(dot(p - a, ab) / max(dot(ab, ab), 1e-8));
    float  d  = length(p - (a + ab * u));
    s += TouchFalloff(d, touch.radius * radiusScale);
}
float K   = injectRate * dt;                       // считается на CPU
float cur = FieldWrite[id.xy];
FieldWrite[id.xy] = cur + max(maxValue - cur, 0) * (1 - exp(-K * s));
```

Решения и почему:

**(a) Аддитивный, но с мягким потолком.** Пока `dye ≪ maxValue` и `K·s ≪ 1`, приращение ≈ `injectRate · dt · s · maxValue` — это обычный аддитив: краска накапливается пропорционально времени под кистью. Потолок `maxValue` нужен потому, что чистый аддитив без предела раздувает пятно при удержании, уходит за диапазон `colorScale` и снова рисует клуб. Форма `1 − exp(−K·s)` выбрана, потому что она **точно** композируется по времени: `n` шагов по `dt/n` равны одному шагу `dt` (при неподвижной кисти). Для неподвижной кисти это делает впрыск точно независимым от `dt` и даёт точный гейт G4; для движущейся остаётся член порядка `dt` (§2c). Чистый аддитив получается при `maxValue` ≫ реальных значений (например `1000`); отдельный режим не заводим.

**(b) Следствие, которое решение владельца принимает осознанно: густота штриха зависит от скорости жеста.** Текселю под кистью достаётся `∫ s dt ≈ (2·radius/3)/v` секунд веса: медленный мазок плотнее, быстрый бледнее. Пик на оси ≈ `maxValue · (1 − exp(−injectRate · (2·radius/3) / v))`. Для скриптованного жеста F2.3 (`v ≈ 32` ед./с, `radius = 1`) это ≈ 0.0208 с под кистью; при `injectRate = 60` пик ≈ 0.71 `maxValue`. Это расчётная оценка, а не замер — Шаг 4 ТЗ печатает фактический пик вдоль оси жеста. Медленный палец насыщает потолок почти мгновенно и выглядит как жёсткий штрих; `injectRate` — порог скорости, выше которого штрих блекнет.

**(c) Расстояние до отрезка `[pos − delta, pos]`, не до точки.** Точечный штамп оставляет пунктир, когда шаг кисти за кадр больше радиуса (при 30 FPS и жесте F2.3 шаг ≈ 1.07 ед. против радиуса 1). Капсула делает ширину независимой от FPS. Небольшая поправка: капсула считает кисть присутствующей на всём отрезке весь кадр, поэтому суммарный вес даёт `≈ (2r/3 + O(dt))/v`; на 60 FPS отклонение несущественно, а гейтом не проверяется.

**(d) Несколько touch суммируются** (`s = Σ f_t`), а не `max`: согласовано с аддитивным законом. Два одинаковых touch эквивалентны удвоенному `injectRate` (G5).

**(e) `touch.strength` не используется.** Для velocity он множитель импульса (10); для dye насыщал бы профиль в жёсткий диск. Яркость задают `injectRate` и `maxValue`.

**(f) Монотонность и потолок.** Впрыск никогда не уменьшает dye (`out ≥ in`); там, где `in ≥ maxValue`, поле не меняется бит-в-бит; `out ≤ max(in, maxValue)`. Билинейная адвекция выпукла, поэтому `max(dye) ≤ maxValue` сохраняется на всём прогоне при условии, что и сид не превышает `maxValue` (оба равны 1).

**(g) Оговорка по R16.** `dye` хранится в `R16_SFloat`: при очень малых `K·s` приращение меньше половины ulp и в хвостах профиля может «залипать» (порядок 2·10⁻⁴ вблизи 0.5). При `injectRate ≥ 20` и 60 FPS не проявляется. Не гейт; смотреть на visual.

#### 3. Место в цепочке, состав пресета

Новый ассет — техника, не номер фазы: **`Assets/Effects/Fluid2D_DyeInject.asset`**. Клон `Fluid2D_HighResDye.asset` (4 поля, dye 512² / остальные 128², `Size=32`, форматы как везде) с тремя отличиями — и **только** ими:

1. `SeedScalarDiskPass.RadiusUV = 0.04` вместо `0.16` (центр `(0.5, 0.5)`, `Value = 1` без изменений);
2. сразу после `SeedScalarDiskPass` добавлен `TouchInjectScalarFieldPass` (`fieldName="dye"`, `injectRate=60`, `maxValue=1`, `radiusScale=1`);
3. цепочка и поля остальное — как в F3.0.

```
TouchInjectVelocity → SeedScalarDisk(dye, r=0.04) → TouchInjectScalar(dye) → Divergence → ZeroMean
  → Jacobi×40 → Subtract → SolidWall → AdvectVelocity → SolidWall → AdvectScalar(dye, velocity)
```

11 пассов. Без VC, без MacCormack. `AdvectScalarPass.DissipationRate = 0` в пресете **по умолчанию** (§3a: чистое сравнение с F3.0). Меню `Tools/M3D/Create Fluid2D DyeInject Experiment` / `Tools/M3D/Assign Fluid2D DyeInject Experiment To Scene`.

**Замечание о сиде.** Тонкий сид стоит в центре `(0.5, 0.5)`, а жест F2.3 идёт `(0.5,0.25) → (0.5,0.75)`, то есть сид лежит прямо на пути жеста. Радиус 0.04 UV ≈ 1.28 ед. — порядка ширины кисти, поэтому вклад сида в картинку сопоставим со штрихом. Чтобы отделить вклад штриха от вклада сида в visual, B0 = тот же ассет с `SeedScalarDisk.Value = 0` (правка в инспекторе, без Create; §6). Порядок «Emit до Simulate» совпадает с пайплайном в [`architecture.md`](../architecture.md); `SimulationWorld` пассы по `Category` не сортирует, порядок — как в `EffectAsset.Passes` (подтверждено Шагом 0).

#### 3a. Затухание краски: как параметризовать

**Рекомендация — не писать новый код. Использовать существующий `AdvectScalarPass.DissipationRate`.**

Он уже делает ровно то, что нужно: `dye ← sample(dye) · exp(−λ·dt)`, где `λ = DissipationRate` в 1/с. Свойства:

- **Экспоненциальный закон, в секундах реального времени.** `dt` приходит как `deltaTime × SimulationSpeed`, поэтому затухание не зависит от FPS и честно масштабируется с `SimulationSpeed`.
- **Бесплатно по пропускной способности.** Множитель сидит в том же кернеле адвекции, который и так читает и пишет `dye` 512². Отдельный пасс затухания добавил бы лишнее чтение и запись поля 512² (R16) в кадр.
- **Live-параметр** (пушится каждый кадр, см. `SetParams`): оператор крутит ползунок в Play без Rebuild.
- **Равномерно по всему полю**: гасит и штрих, и сид.

Удобная параметризация — через **период полураспада** `t½ = ln 2 / λ`, а не через сырой `λ`:

| `DissipationRate` λ, 1/с | `t½`, с | Через 10 с остаётся |
| ------------------------ | ------- | ------------------- |
| 0                        | ∞       | 100 %               |
| 0.07                     | ≈ 10    | 50 %                |
| 0.15                     | ≈ 4.6   | 22 %                |
| 0.3                      | ≈ 2.3   | 5 %                 |
| 0.5                      | ≈ 1.4   | 0.7 %               |
| 1.0                      | ≈ 0.69  | 0.005 %             |

Практические следствия:

- **Тонкая нить гаснет раньше толстого клуба.** Экспонента делит все значения на одно и то же; время, за которое пик нити `P` упадёт ниже порога видимости `θ`, равно `ln(P/θ)/λ`. У штриха с пиком 0.4 оно короче, чем у сида с пиком 1.
- **Взаимодействие с впрыском.** Под неподвижной кистью равновесие (по центру, без учёта переноса) `dye_eq = maxValue · injectRate / (injectRate + λ)`. При `injectRate = 60` и `λ ≤ 1` это ≥ 98 % потолка: затухание заметно только после ухода кисти.
- **Стартовые значения для visual:** `0` (чистое сравнение A/B с F3.0, оно же значение пресета), затем `0.15` и `0.5`.

Чего не делать: отдельный `DecayFieldScalarPass` на `dye` (лишний проход по 512², ping-pong); линейное вычитание `dye −= c·dt` (жёсткий срез вместо постоянной времени, тонкие нити исчезают резко и зависят от значения пика); хранение «возраста» краски во втором поле (второе поле 512², вне задачи).

Если после visual выяснится, что нужно затухание, **не равномерное по полю** (например, быстрее гасить штрих, но не сид), — это отдельный тикет и, вероятно, отдельный `decayRate` в самом `TouchInjectScalarFieldPass`; сейчас не заводить.

#### 4. Числовые гейты (EditMode, синтетика, R32)

Кернел меряется отдельно от живой цепочки, как F3.0 §3. Поле `Size=32`, `dt` задаётся в тесте. Формула профиля — из §2: `v(d) = maxValue · (1 − exp(−injectRate·dt·f(d)))`, `f(d) = (1 − d/R)²`, `R = radius·radiusScale`.

| #   | Что                                        | Гейт                                                                                                                                                                                                        |
| --- | ------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| G1  | Точечный штамп, `delta=0`, предзаполнено 0 | значение в текселе на расстоянии `d` равно `v(d)` (1e-4) для нескольких `d`; центр — `v(0)`; на `d ≥ R` строго 0                                                                                            |
| G2  | Монотонность, потолок                      | поле предзаполнено: левая половина `0.9`, правая `0.2`, `maxValue = 0.5`: везде `out ≥ in`; левая половина (`in ≥ maxValue`) бит-в-бит без изменений; правая `out ≤ 0.5`                                    |
| G3  | Капсула                                    | длина `delta` равна `3·radius`: тексели в начале, середине и конце отрезка (центрированные на текселе) равны `v(0)` (1e-4); тексель на `0.5·R` по перпендикуляру от середины равен `v(0.5R)`                |
| G4  | Независимость от FPS (неподвижная кисть)   | `delta=0`: один вызов `dt` ≡ `n` вызовов `dt/n` подряд (`n = 4`) — поле поэлементно `1e-5`                                                                                                                  |
| G5  | Несколько touch                            | (а) два **одинаковых** touch ≡ один touch с `injectRate × 2` (1e-5); (б) два touch на расстоянии больше `2R` друг от друга: поле поэлементно равно сумме двух отдельных прогонов (носители не пересекаются) |
| G6  | `TouchCount = 0`                           | поле бит-в-бит без изменений                                                                                                                                                                                |
| G7  | `injectRate = 0`                           | поле бит-в-бит без изменений                                                                                                                                                                                |
| G8  | Cross-res                                  | один и тот же мировой штрих на `dye` 128² и на 512² (тот же `Size`): интеграл `Σ dye·(Size/Resolution)²` расходится **не более 3 %**                                                                        |
| G9  | `radiusScale = 0.5` против `1`             | сетка 256² (тексель 0.125), touch в центре текселя, `delta=0`; вдоль U `d = k·0.125`, `k = 0…9`, при `radiusScale` 1 и 0.5 значение равно `v(d)` (1e-4); тексель `d = 0.75` равен 0 при 0.5 и больше 0 при 1 |

Живая цепочка (128²/512², Jacobi×40, эмуляция жеста F2.3 по кадрам, затем кадры без touch до ~3 с): нет NaN/Inf; `min(dye) ≥ 0`; `max(dye) ≤ maxValue + 1e-3` на каждом кадре; сразу после последнего кадра штриха `dye > 0.05` в окне `±radius` у каждой из пяти точек пути `UV.y ∈ {0.25, 0.35, 0.5, 0.65, 0.75}` — **только в прогоне с `Seed.Value = 0`**: точка `0.5` лежит в центре сида, и в прогоне с сидом порог выполнится без штриха (а адвекция может донести сид и до соседних точек). В прогоне с сидом (как в пресете) проверяются только безопасность и потолок. **Логируется, не гейтится:** пик dye на оси жеста в прогоне с `Seed.Value = 0` (калибровка оценки §2b и `injectRate`); ширина нити (FWHM поперёк жеста, середина пути, от локального пика) на 512² и на варианте dye 128², через 0.5 с и 3 с; `elapsedMs/N` цепочки (рядом с F3.0 `0.184`, [Techdebt 8k](../last/Techdebt.md)).

#### 5. Размещение кернела — без новой записи в passLibrary

Список compute-файлов продублирован минимум в семи местах (`M3DDemoTools.cs` и шесть world-smoke тестов). Новый `.compute` = правка всех. Кернел `TouchInjectScalar` кладётся в **существующий** `Assets/Shaders/GPU/Passes/TouchGrayScottPasses.compute` (там уже `Touch.hlsl`, `Touches`/`TouchCount`, `RWTexture2D<float>`). Имя файла вводит в заблуждение, переименование вне скоупа. Подтверждено Шагом 0: `SimContext.FindKernel` перебирает всю `passLibrary` и берёт первый шейдер с таким kernel, поэтому новый kernel в `TouchGrayScottPasses.compute` подхватится без правок списков.

#### 6. Visual (оператор, не гейтит NUnit)

Протокол по образцу [`play-F3.0-touch.md`](../last/play-F3.0-touch.md): `ScriptedTouchStroke` F2.3 (`(0.5,0.25)→(0.5,0.75)`, `Duration 0.5`), `SimulationSpeed=1`, GroundXZ, мышь в Play не трогать.

- **A** = `Fluid2D_HighResDye.asset` — опорный кадр F3.0.
- **B** = `Fluid2D_DyeInject.asset`, `DissipationRate = 0`.
- **B0** = B с `SeedScalarDisk.Value = 0` (отделяет вклад штриха от вклада сида).
- **B-fade** = B с `AdvectScalarPass.DissipationRate` 0.15, затем 0.5.
- **B-rate** (опц.) = B с `injectRate` 20 и 200 — видеть, как скорость жеста меняет густоту.

Что смотреть: читается ли нить **на всём пути жеста**, а не только ножкой; нет ли пунктира; голова штриха (разворот в вихрь); где штрих блекнет из-за скорости жеста; когда нить исчезает при `DissipationRate > 0`; нет ли Inf/шахматки. Критерий «взято» — владелец: «нить — главный элемент картинки, не остаток гриба». Если штрих остаётся статичной линией без ролл-апа (velocity-жест слишком слаб) — это находка про velocity и повод открыть F3.3, а не чинить в F3.1.

#### 7. Что не входит

- Цветной dye (RGB/палитра, несколько красок).
- Затухание, неравномерное по полю; новый пасс затухания; правка `AdvectScalarPass` (даже атрибут `[Tooltip]` — класс в списке «не менять»).
- Gate по движению; режим `max`.
- Смена формы кисти velocity, `touchRadius`/`touchStrength` в `InputRouter`.
- VC, MacCormack (dye и velocity), `dyeMacScratch`, F3.2, F3.3, второй Poisson, подъём Jacobi, подъём `velocity`-разрешения, `dye` на `R32_SFloat`, `deltaTime` clamp (F0.7).
- Правка `AdvectScalar`/`AdvectVelocity`/`SeedScalarDisk`/`TouchInjectVelocity`/`TouchInjectGrayScott`, валидаторов, `ValidateMatchingFieldGeometry`.
- Переименование `TouchGrayScottPasses.compute`.

### Отклонённые варианты

**`max`-блендинг (первая редакция этого ADR).** Идемпотентен и не зависит от скорости жеста, но владелец выбрал аддитив: накопление при медленном мазке — желаемое поведение.

**Чистый аддитив без потолка.** Раздувается при удержании, уходит за `colorScale`, не композируется по `dt` так же аккуратно; воспроизводит клуб. Получается как частный случай `maxValue` ≫ 1.

**Линейная форма `cur + rate·dt·s`, затем `min(·, maxValue)`.** Тоже ограничена, но «n шагов по `dt/n` = один шаг `dt`» держится только до клампа, и гейт G4 теряет точность; кроме того, при больших `dt` (clamp в мире нет) резкий срез. Экспоненциальная форма устойчива при любом `dt`.

**Точечный штамп.** Пунктир на быстрых жестах и при низком FPS.

**`touch.strength` как яркость.** Насыщает профиль в жёсткий диск.

**Новый `.compute`-файл.** Правка семи списков без выигрыша; §5.

**Отдельный `DecayFieldScalarPass` для краски.** Лишний проход по `dye` 512² в кадр при том, что `AdvectScalarPass.DissipationRate` уже затухает внутри адвекции.

**Линейное затухание краски.** Жёсткий срез, нет постоянной времени.

**Оставить жирный сид `0.16`.** Снова клуб, штрих не виден; владелец решил сжать сид до `0.04`.

### Последствия

- (+) Источник dye — тот же жест, что и velocity: нить по всему пути, ширина = кисть × `radiusScale`; на 512² штрих ≈ 16 текселей поперёк против ≈ 4 на 128² (при `touchRadius = 1`).
- (+) Неподвижная кисть точно не зависит от `dt` (экспоненциальная форма композируется); у движущейся капсулы остаётся член порядка `dt` (§2c), на 60 FPS малый. Потолок защищает от раздувания.
- (+) Затухание не требует нового кода: существующий live-параметр `DissipationRate`, бесплатный по bandwidth.
- (+) Пасс generic, пригоден для другого скаляра.
- (+) Дифф небольшой: один кернел, один класс, один пресет; существующие пассы и ассеты не меняются.
- (−) Густота штриха зависит от скорости жеста (следствие аддитива, §2b); `injectRate` — крутилка этого порога, значение 60 — оценка, а не замер.
- (−) Тонкий сид лежит на пути жеста; вклад сида отделяется только вариантом B0.
- (−) Не лечит диссипацию velocity ([Techdebt 5](../last/Techdebt.md)): если velocity-жест слабый, нить остаётся статичной линией; это сигнал на F3.3.
- (−) Кернел лежит в файле с именем про Gray-Scott (§5); долг — в [Techdebt](../last/Techdebt.md) одной строкой.

**Вне скоупа документа:** F3.2, F3.3; цвет dye; подбор итоговых `injectRate`/`radiusScale`/`DissipationRate` (оператор по visual).
