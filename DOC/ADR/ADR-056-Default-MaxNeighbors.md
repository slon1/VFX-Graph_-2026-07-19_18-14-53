# ADR-056: значение `maxNeighbors` по умолчанию 128

**Статус:** предварительно (2026-10-29).
**Дата:** 2026-10-29.
**Контекст:** ветка `feature/classic-boids`, после F5 и фазы А (`a296855`). Уточняет [ADR-052](ADR-052-Accepted-Neighbor-Cap.md) §6. Номера 054 и 055 на этой ветке заняты, 044 зарезервирован под P8.

## 1. Решение

Значение по умолчанию поля `BoidNeighborForcePass.maxNeighbors` — 128 для нового пасса. Двенадцать существующих ассетов и билдеры старых пресетов остаются на 48 ради совместимости с тестами.

## 2. Почему 128

Это временная цена, а не принятая картинка. Play (F5.2) принял только кап 192, кап 128 не принят. Кап 192 на S200 не проходит M1: кадр режима B 36,01 мс и 126,79 цикла на частицу при полосе M2 45–58, с рендером 40,10 мс (около 25 кадров/с). Кап 128 даёт 24,86 мс без рендера. Владелец по наблюдению на больших скоплениях (400 000 частиц) считает, что разница между 48 и 192 на итоговой картинке слабая по сравнению с обходом всех соседей (кап 0). Это наблюдение владельца, моделью и измерением не проверено, и оно расходится с отметкой Play для 128.

## 3. Цена

Цена обхода растёт линейно с капом, около 0,15 мс на единицу на S200: 6,99 / 18,92 / 28,96 мс для 48 / 128 / 192 (`DOC/MEASURE/521a98b-a9d40c4d/F5-report.md`).

Оценка кадра для 128 с рендером: `24,86 + (40,10 − 36,38) = 28,58` мс. Это кадр режима B капа 128 плюс стоимость рендера, взятая с капа 192 (3,72 мс). Допущения: рендер стоит одинаково при любом капе, частота около 700 МГц. Это оценка, не измерение. Захвата для 128 нет.

## 4. Что не проверено

- Кап 128 с рендером на S200.
- Устойчивая частота (433 МГц) в этой серии.
- Визуальный вывод основан на Play и наблюдении владельца, не на модели.
- Play шёл на сценах 3000 и 100 000 частиц.

## 5. Когда пересматривать

- После P8.
- После проверки ячейки меньше радиуса в CPU-модели. Оценка ревью, не измерение: `DOC/MEASURE/p6-cpu-model/cell_geometry.py`, равномерная плотность. При том же числе принятых соседей эквивалентные капы относительно 192 равны 174 / 133 / 115 для пропуска ячеек / ячеек R/2 / R/2 с пропуском, то есть ниже в 1,1 / 1,4 / 1,7 раза.
- После возврата суммы отталкивания. [ADR-053](ADR-053-Sum-Separation.md) §3 и §6: сумма держит стаю при `maxNeighbors = 0` и рвёт её вдоль решётки при положительном капе.
- При появлении данных об устойчивой частоте.

## 6. Связь с усреднением отталкивания

Пока отталкивание усредняется (`sep / sepN`), смена капа меняет только выборку соседей, а не масштаб силы. При сумме масштаб зависел бы от капа примерно в 2,6 раза между 48 и 128. Это оценка ревью: принятых соседей около 35% посещённых, то есть около 17 при капе 48 и около 45 при капе 128, а измеренное отношение цены обхода 128/48 равно 2,71. В ADR-053 такого числа нет.

## 7. Отвергнутые варианты

- 192 по умолчанию: не проходит M1 на S200.
- 48 по умолчанию: визуально худший, владелец.
- Один кап для всех сцен навсегда: цена растёт с числом частиц, значение остаётся полем ассета.

## 8. Последствия

Инициализатор 128 действует на пас, добавленный с нуля. Дубликат старого пресета наследует 48, значение в дубликате ставят вручную. Два меню старых пресетов остаются на 48 и обязаны дать 48, пока это решение не отменено. Серии на новых пресетах запускать с `-MaxN 128`, серии на старых без изменений. Новый ассет записывает значение явно, поэтому будущая смена поля по умолчанию старые ассеты не заденет.

На этой ветке пас создают три билдера, все с явным `MaxNeighbors = 48`: `CreateBoidsHashAsset`, `CreateBoidsHashTwoTeamsAsset` и `CreateBoidsHashClassicAsset`. `Boids_hash_classic` и `Boids_hash_classic_points` собраны по рецепту `Boids_hash` для сравнения и остаются на 48 по замыслу. В тест `ExistingEffects_StayAt48` они не входят: его список из 12 имён не менялся. Новый билдер, которому нужны 128, должен задать значение явно или не задавать вовсе. Способа собрать старые билдеры в памяти нет: они пишут файл, поэтому отдельного теста на них в фазе А нет.

## 9. Отклонение фазы А

`Boids_hash_2teams.asset` хранил `maxNeighbors: 128` (остаток правок владельца, коммит `147147c`). В `a296855` возвращено 48. В том же ассете остались поля `sumSeparation: 1` и `sameTeamCap: 1`, которых нет в коде пасса. Unity их игнорирует и отбросит при следующем сохранении ассета. В этом ТЗ они не снимались.
