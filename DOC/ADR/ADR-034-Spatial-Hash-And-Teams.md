### Контекст

Цель проекта сместилась на Reynolds Boids в стиле Rivalry: постоянная скорость, ограниченный поворот, несколько стай с отталкиванием чужих. `Boids_mk1` (ADR-012) считает соседей через поля (P2G → градиент). Поле усредняет по текселю: нет отдельных соседей, нет отличия «свой/чужой», нет точной дистанции. Для Rivalry-поведения нужен поиск соседей по частицам.

[Techdebt](../last/Techdebt.md) п. 11 запрещал начинать spatial hash, пока field-surrogate хватает. Этим ADR гейт **снят**: владелец проекта сделал Reynolds Boids следующей целью, а они требуют соседей по частицам.

П. 12 (унификация `ParticleSet` / `FieldSet` / hash) **не начинается**. Хэш вводится как ресурс, которым владеет пасс, а не как третий тип ресурса мира (§1). Поэтому триггер п. 12 («появление третьего типа ресурса») не срабатывает.

Кинематическая цепочка уже есть (ADR-012): `ClearVelocity` превращает `velocity` в аккумулятор силы без `dt`, `HeadingSteer` делает nlerp курса к направлению силы и выставляет скорость. Не хватает только силы соседей.

### Решение

#### 1. `SpatialHashSet` — ресурс, которым владеет пасс

`BuildSpatialHashPass : SimPass, IDisposable` создаёт `SpatialHashSet` в `Initialize` и кладёт в `SimContext.SpatialHash`. Освобождает в `Dispose`, мир уже вызывает `Dispose` у пассов в `Teardown`. Прецедент — `ZeroMeanScalarPass`, у которого собственный `GraphicsBuffer`.

Потребители (силовой пасс P5 и далее) помечаются интерфейсом `ISpatialHashConsumer` и в своём `Initialize` берут `context.SpatialHash`. Если его нет — `InvalidOperationException`. Второй билдер на том же контексте тоже бросает. `SpatialHashValidator` на Build дублирует эти проверки понятным текстом и проверяет согласованность с `BoxBounds`.

Почему не ресурс мира: мир не должен знать про хэш (никаких доменных веток в `SimulationWorld`). Конфиг сетки естественно живёт на пассе, который её строит. Конструктор `SimContext` не меняется: `SpatialHash` — свойство с `internal set`, тесты собирают контекст как раньше.

#### 2. Сетка и тор

Плоскость XZ, Y игнорируется. Линейный индекс `y * res.x + x`, без Morton.

```
origin = center.xz - extents.xz
size   = 2 * extents.xz
res    = max(1, floor(size / minCellSize * (1 + 1e-5)))   // по каждой оси
cell   = size / res                                       // >= minCellSize с точностью 1e-5
```

Ячейки точно покрывают мир. `cell` может быть меньше `minCellSize` не больше чем на относительные `1e-5`. Все сравнения «радиус ≤ ячейка» идут с этим допуском.

Режим `wrap` (поле билдера):

- `true` — мир тор (`BoxBounds` Wrap). Индекс ячейки по модулю `res`: позиция ровно на верхней границе попадает в ячейку 0, чуть ниже нижней — в последнюю. Соседние ячейки по модулю. Смещение до соседа — кратчайшее (`d - size * round(d / size)`). Требуется `res >= 3` по каждой оси, иначе заворот даёт одну ячейку дважды.
- `false` — индекс клампится в `[0, res-1]`, ячейки за краем пропускаются, кратчайшего смещения нет.

Инварианты, ошибки без коррекции: `res.x * res.y <= 65536` (лимит двухуровневого блочного скана 256 × 256); `res >= 3` при `wrap`. Проверяются и в `Initialize` билдера, и в валидаторе.

Согласованность с миром (валидатор): при `wrap = true` обязателен включённый `BoxBounds` Wrap с теми же `center.xz` / `extents.xz` (допуск 1e-3). Без заворота в мире хэш завернул бы частицы сам, и через шов появились бы фантомные соседи. При `wrap = false` включённый `BoxBounds`, если он есть, обязан быть Bounce с теми же границами. Если `BoxBounds` нет — предупреждение: область могут ограничивать другие пассы, валидатор их не проверит.

#### 3. Построение: шесть кернелов, снимок

Файл `SpatialHashPasses.compute`, один `Execute` билдера:

1. `HashClear` — обнулить счётчики ячеек.
2. `HashCount` — ячейка частицы, `InterlockedAdd` в счётчик. Без groupshared-гистограммы: при 20–200k частиц не нужна.
3. `HashScanBlocks`, `HashScanBlockSums`, `HashAddOffsets` — исключающий префиксный скан, порт блочного Blelloch из Rivalry (`GridUtils.compute`, блок 256). `HashAddOffsets` пишет и начала ячеек, и курсоры (отдельный `InitCellCounters` не нужен).
4. `HashScatter` — слот через `InterlockedAdd` по курсору. В слот сразу пишутся индекс частицы и **снимок**: позиция XZ, курс XZ, команда. Отдельный `ReorderAgents` не нужен.

Снимок нужен ради памяти, а не ради корректности. Силовой кернел не пишет `heading` и `position`, поэтому гонки нет и без снимка. Снимок превращает три случайных чтения на соседа в одно последовательное ценой одной записи на частицу за кадр. Это ставка на скорость, она проверяется A/B-замером на S10 (P7).

Порядок слотов внутри ячейки недетерминирован. Тесты сравнивают множества, а не порядок. Силы сравниваются с CPU-эталоном с допуском.

Число живых частиц: в проекте всегда `ParticleSet.Count == Capacity`. Неспавненных «призраков» нет, диспатчи идут по `Count`. При `Count == 0` билдер ничего не диспатчит и буферы частиц не создаёт.

`RepeatCount` у билдера и потребителей не переопределяется (1). Повтор силового пасса учёл бы силу дважды.

#### 4. Команды — список на `EffectAsset` (P4)

`TeamProfile` (до 8): радиусы и веса separation / alignment / cohesion, `interGroupSeparationMultiplier`, `cruise`, `turn`, градиент цвета. Один источник правды для силы, steer и палитры. Мир каждый кадр заливает маленький `GraphicsBuffer<TeamParams>` (3 × float4) и отдаёт его через `context.Teams`, как `touchBuffer`. Межроевая модель — паритет с Rivalry: чужие участвуют только в separation с множителем. Матрица пар — опциональная фаза P9.

#### 5. Кинематика первой

Цепочка пресета:

```
BuildSpatialHash
ClearVelocity
BoidNeighborForce        // += sep + align + coh, без dt, соседи только из снимка
[NoiseAccum, TouchAccum] // P8
TeamHeadingSteer         // HeadingSteer дословно, turn / cruise из команды
Integrate
BoxBounds (Wrap)
HeadingToValue
```

`TeamHeadingSteer` — дословная копия ядра `HeadingSteer` (все пять `UnitOr`). Меняются только `TurnSpeed` / `CruiseSpeed` на значения команды. Паритет с `HeadingSteer` проверяется тестом. Steer идёт к направлению силы: абсолютные веса не важны, важны их отношения.

Ньютонов вариант (`velocity += force * dt`) — только опциональная фаза P9.

#### 6. Палитра команд (P6a)

`teamId` + 2D LUT (строка на команду) поверх существующего `value` (ADR-031). Атрибута цвета на частицу нет.

### Отклонённые варианты

**Hillis–Steele скан с ping-pong.** 14–16 диспатчей на кадр против трёх. Блочный скан Rivalry уже работал.

**Хэш как ресурс мира рядом с `FieldSet`.** Доменная ветка в `SimulationWorld` и преждевременный шаг к Techdebt 12.

**Поиск соседей без тора, как в Rivalry.** На Wrap-мире у шва нет соседей. На сетке 25 × 25 это 96 из 625 ячеек.

**Clamp к `res >= 3`.** Молча делал `cell < minCellSize` и терял соседей. Заменён ошибкой.

**Атрибут `ParticleColor` (Float4) и `ParticleColorMode` в шейдере.** Дублирует ADR-031 и стоит 16 байт на частицу.

**Матрица отношений команд N × N в первой версии.** В Rivalry её нет, это новая фича.

**Отдельный debug-биндер и шейдер сетки.** Счётчики ячеек пишутся в объявленное поле и показываются существующими `DebugFieldQuads` (P2).

**Ньютонова версия первой.** Противоречит цели (постоянная скорость) и выводу ADR-012.

**Groupshared-гистограмма и Morton-индекс Rivalry.** Нужны на сотнях тысяч частиц. Возвращаются только по замеру P7.

### Последствия

- (+) Соседи по частицам без правок мира. Хэш — обычный пасс в списке.
- (+) Тор агентов и тор соседей совпадают по построению.
- (+) Снимок и скан проверяются против CPU-эталона до появления любой силы.
- (−) Конфиг сетки дублирует границы `BoxBounds`. Держит валидатор, а не единый источник.
- (−) Атомарный scatter недетерминирован: при срабатывании капа соседей (P5) набор учтённых соседей может дрожать от кадра к кадру. Проверяется метрикой в гейте 5c.
- (−) Замер S10 (квады включены): 100k ещё на потолке 60 FPS, хэш заметен с 500k. Режимы без рендера не снимались. Цифры в [`status.md`](../status.md).
