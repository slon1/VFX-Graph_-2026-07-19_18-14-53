## ADR-051: Vorticity Confinement поверх DyeInject (F3.4, вариант E1)

**Статус:** Предложено. EditMode зелёный (2026-10-21, §4). Станет «Принято» только после visual владельца (§5) и явного слова владельца.
**Дата:** 2026-10-21
**Контекст:** M3D Framework, после F3.1 ([ADR-050](ADR-050-Continuous-Dye-Injection.md), принят). Ветка `feature/reynolds-boids`, трек stable-fluid.
**План:** [`plan-stable-fluid.md`](../plan-stable-fluid.md) §4, новая строка F3.4 (F3.2 и F3.3 не открыты; номер взят следующим по порядку)
**ТЗ:** [`todo-F3.4.md`](../last/todo-F3.4.md)
**Не меняет в этом ADR:** кернелы и классы всех пассов (включая `VorticityConfinementPass` и его кернел, [ADR-027](ADR-027-Vorticity-Confinement-Pass.md)); `TouchInjectScalarFieldPass`; валидаторы; все существующие `Fluid2D*.asset`, включая `Fluid2D_DyeInject.asset`.

### Контекст

F3.1 дала то, что искали: на dye 512² жест рисует нить по всему пути, нить не статичная (visual владельца 2026-10-21). Открытый вопрос — можно ли усилить мелкомасштабную структуру нити: свернуть её в вихревые завитки, а не только вытянуть.

Vorticity Confinement (VC) на `velocity` 128² уже есть и проверен:

- F2.1/F2.1b ([ADR-027](ADR-027-Vorticity-Confinement-Pass.md)): торнадо у рамки снимает маска `BorderMargin = 2`; ширину не расширять.
- F2.3 visual: на жирном пятне (диск `radiusUV = 0.16`) VC даёт «жилковатый интерьер, не макро-нить» ([Techdebt 8l](../last/Techdebt.md)). На тонкой нити не пробовали — это и есть гипотеза.
- VC только усиливает уже существующую завихрённость, а velocity в `Fluid2D` быстро затухает ([Techdebt 5](../last/Techdebt.md)). Эффект может быть заметен только в первые секунды после жеста.

### Гипотеза

Если добавить VC в цепочку `Fluid2D_DyeInject` (одним пассом, перед проекцией), то на тонкой нити dye 512² появятся вихревые завитки без разрыва нити на клубы, и без возвращения торнадо у рамки. Отрицательный результат тоже результат: пустой кадр записывается как находка с кандидатами (§5), следующий тикет заранее не выбирается.

### Решение

#### 1. Единственная переменная — один пасс VC

Новый ассет: **`Assets/Effects/Fluid2D_DyeInjectVC.asset`**. Клон `Fluid2D_DyeInject.asset` (поля, форматы, `Size`, параметры `SeedScalarDiskPass` (`RadiusUV = 0.04`) и `TouchInjectScalarFieldPass` (`injectRate = 60`, `maxValue = 1`, `radiusScale = 1`), `DissipationRate = 0`) с **одним** отличием:

- добавлен `VorticityConfinementPass { VelocityField = "velocity", EpsilonVc = 1, BorderMargin = 2 }` **сразу после `TouchInjectScalarFieldPass` и перед `DivergenceFieldPass`**.

```
TouchInjectVelocity → SeedScalarDisk(dye, r=0.04) → TouchInjectScalar(dye) → VorticityConfinement(ε=1, m=2)
  → Divergence → ZeroMean → Jacobi×40 → Subtract → SolidWall → AdvectVelocity → SolidWall → AdvectScalar(dye, velocity)
```

12 пассов. Параметры VC — как на `Fluid2D_Vorticity` ([ADR-027](ADR-027-Vorticity-Confinement-Pass.md), F2.1b); `ε` меняется оператором в Play, это live-параметр.

**Почему перед Divergence, а не после `AdvectVelocity`.** VC добавляет силу в velocity. Если поставить его после проекции, сила останется непроецированной: `AdvectScalar` перенесёт dye по скорости с ненулевой дивергенцией. Перед `Divergence` сила попадает в проекцию. Так же устроен `Fluid2D_Vorticity` (VC перед Divergence), хотя там порядок Harris (Advect → Project): относительно проекции позиция та же. Отличие по кадру: в `Fluid2D_Vorticity` `AdvectVelocity` идёт до VC в том же кадре, а здесь после проекции, то есть VC читает velocity, перенесённую в прошлом кадре. Это сдвиг на кадр, не повод менять порядок; E2/E3 вне этого тикета.

**Почему VC после `TouchInjectScalar`, а не между touch-пассами.** Порядок внутри Emit-группы для velocity не важен: VC читает velocity, а `TouchInjectScalar` пишет только dye. VC ставится после обоих Emit-пассов, непосредственно перед проекцией.

Что остаётся как в DyeInject: сид тонкий, dye 512² / velocity 128², `AdvectScalarPass.DissipationRate = 0` (затухание оператор крутит живьём), Jacobi×40, два `SolidWall`.

Меню: `Tools/M3D/Create Fluid2D DyeInjectVC Experiment` / `Tools/M3D/Assign Fluid2D DyeInjectVC Experiment To Scene`. `Assign` берёт `SimulationWorld` **активной** сцены (как у F3.1).

#### 2. Квадратный тексель и разрешение

`VorticityConfinementPass.RequiresSquareTexel = true`; `velocity` 128² при `Size = 32×32` даёт квадратный тексель 0.25, валидатор проходит. Разрешение `dye` 512² VC не читает и не пишет, cross-res ему не нужен.

#### 3. Что не входит (явно)

- Порядок Harris (E2, E3), limited MacCormack dye (E4), `dyeMacScratch`.
- Правка `VorticityConfinementPass`, кернела `VorticityConfinement`, маски `BorderMargin`, значения `ε` по умолчанию, `TouchInjectScalarFieldPass`.
- F3.2 (reflect вместо clamp в стенсиле VC), F3.3 (MacCormack на velocity).
- Цветной dye, неравномерное затухание, новый пасс затухания.
- Gate по движению, `max`-режим впрыска.
- Все существующие `Fluid2D*.asset` — не трогать, Create не вызывать.
- Мобильная адаптация, рендер частиц.

#### 4. Числовые гейты (EditMode)

Нового кернела нет, поэтому кернел-гейтов нет. Гейты — композиция пресета и безопасность живой цепочки.

| # | Что | Гейт |
| --- | --- | --- |
| P1 | Состав пресета (не GPU) | 4 поля как у DyeInject; **12 пассов** строго в порядке §1; ровно один `VorticityConfinementPass` (`VelocityField = "velocity"`, `EpsilonVc = 1`, `BorderMargin = 2`) между `TouchInjectScalar` и `Divergence`; один `SeedScalarDiskPass` (`RadiusUV = 0.04`, `Value = 1`); один `TouchInjectScalarFieldPass` (`injectRate = 60`, `maxValue = 1`, `radiusScale = 1`); нет `CopyScalar`, `LimitedMacCormackCombine`; два `SolidWall`; `DissipationRate = 0`; `Jacobi = 40` |
| P2 | World smoke | ассет **с диска**, `Rebuild()` не бросает, `world.enabled == true`; список `passLibrary` скопировать целиком из `Fluid2DVorticityWorldSmokeTests` (кернел `VorticityConfinement` лежит в `FluidPasses.compute`; списки Vorticity- и DyeInject-теста совпадают, `TouchGrayScottPasses.compute` включён, добавлять ничего не нужно) |
| L1 | Живая цепочка, прогон S (сид как в пресете) | на каждом кадре: нет NaN/Inf в `dye` и `velocity`; `min(dye) ≥ 0`; `max(dye) ≤ maxValue + 1e-3`. Проверка NaN/Inf — **и в базовом прогоне V0-N**: разность скоростей не должна сравниваться с битой базой |
| L2 | Живая цепочка, прогон N (`Seed.Value = 0`) | то же, что L1; плюс (а) в кадре, когда кисть проходит каждую из пяти точек пути `UV.y ∈ {0.25, 0.35, 0.5, 0.65, 0.75}`, `dye > 0.05` в окне `±radius` вокруг этой точки (инъекция работает при VC в цепочке); (б) сразу после последнего кадра штриха `dye > 0.05` в окне `±radius` у **головы** (`UV.y = 0.75`). Четыре ранние точки после штриха — **только в лог**: гипотеза в том, что нить за 0.5 с свернётся и уйдёт с оси, и жёсткий гейт остановил бы удачный прогон |
| L3 | VC действительно работает | сравнение с прогоном той же цепочки **без VC** (V0): максимум нормы разности скоростей `u_V1 − u_V0` во внутренних текселах (дальше двух от рамки) строго больше `1e-6` хотя бы на одном кадре за 3 с. Порог ниже шага R16: гейт значит лишь «буферы различаются» и размер эффекта не мерит; сам максимум и номер кадра пишутся в лог |

Живой GPU-тест помечается `[Timeout(900000)]`, как штрих F3.1. Геометрия живых прогонов — 128² / 512², `Size = 32`, Jacobi×40, сценарий жеста F2.3 как в F3.1 ([`todo-F3.1.md`](../last/todo-F3.1.md) Шаг 4; `delta = pos − prev`, первый кадр `delta = 0`).

**Логируется, не гейтится** (V0 против V1, прогон N, рядом на одном и том же жесте):

- `max |ω|` (внутри) сразу после штриха и через 3 с;
- `max |u|` в кольце рамки (текселы 0–1, где работает маска) и в третьем текселе — детектор торнадо: печатаются **оба** значения (V0 и V1) раздельно, без отношения: у V0 может быть ноль, и отношение ничего не скажет; заметный рост у V1 — находка;
- `max` нормы разности `u_V1 − u_V0` во внутренних текселах и номер кадра, на котором он достигнут (L3);
- кинетическая энергия `Σ|u|²` сразу после штриха и через 3 с;
- пик `dye` на оси жеста и FWHM нити поперёк жеста (`y = 0.5`) сразу после штриха и через 3 с, для 512²;
- `elapsedMs/N` цепочки из 12 пассов (cpu/driver, не порог), строка рядом с F3.1 `0.373`.

Решает visual, не логи: по ним нет порогов, чтобы не плодить флаки из шума адвекции.

#### 5. Visual (владелец)

Протокол по образцу [`play-F3.1-touch.md`](../last/play-F3.1-touch.md). Жест — `ScriptedTouchStroke` F2.3 (`(0.5,0.25)→(0.5,0.75)`, `Duration 0.5`), `SimulationSpeed = 1`, GroundXZ, мышь в Play не трогать.

- **A** = `Fluid2D_DyeInject.asset` — принятая база F3.1.
- **B** = `Fluid2D_DyeInjectVC.asset`, `ε = 1`.
- **B-ε** = B с `EpsilonVc` 0.5 и 2 (live, в инспекторе).
- **B-fade** = B с `AdvectScalarPass.DissipationRate` 0.15 (при желании; 0.5 уже смотрел как для F3.1).

После B-ε и B-fade вернуть `EpsilonVc = 1` и `DissipationRate = 0` и не сохранять ассет с крутилкой: иначе правка уедет в коммит (как радиус сида когда-то уехал с 0.08 на 0.16).

Что смотреть:

1. Появляются ли завитки/вихревые закрутки вдоль нити, а не просто утолщение или шум.
2. Нить остаётся непрерывной или распадается на клубы / жилки.
3. Нет ли кольца торнадо у рамки.
4. Как долго живёт вихревая структура после жеста (velocity затухает).

Критерий «взято» — владелец. **Пустой кадр** (нет завитков) записывается как находка с тремя кандидатами, без заранее выбранного следующего тикета: (1) velocity слабая или быстро затухает ([Techdebt 5](../last/Techdebt.md)); (2) проекция съела силу VC; (3) вихрь на velocity 128² не доезжает до нити 512². Логи разделяют кандидатов лишь частично: если `max|ω|` у V1 почти равен V0 — кандидаты 1 или 2; если вырос, а завитков нет — кандидат 3. F3.2 тут ни при чём (это стенсиль рамки, не интерьер). Следующий тикет выбирается после этого разбора. Жилковатость, рвущая нить → снижать `ε`; торнадо у рамки → находка по маске.

### Отклонённые варианты

**VC после `AdvectVelocity` (как в `Fluid2D_Vorticity`, но в порядке Project → Advect).** Сила остаётся непроецированной в кадре.

**Сразу три варианта (VC + Harris + MacCormack) в одном пресете.** Три переменные в одном кадре, причину не отделить. Владелец выбрал E1 «а там посмотрим».

**Правка `BorderMargin` или `ε` по умолчанию.** Ширина маски зафиксирована F2.1b, дефолт `ε` не пересматривается.

### EditMode замерено (2026-10-21)

P1, P2, L1–L3 зелёные. `Rebuild` ассета с диска: 4 поля, 12 пассов. Живой жест F2.3, `dt=1/60`, 3 с. Кадры прохождения точек тест выбрал по `Evaluate`: 0, 6, 15, 24 и последний кадр штриха 29 для головы.

`max |u_V1−u_V0|` внутри = `2.218` на кадре 179. Порог `1e-6` только отмечает, что буферы различаются. Число одно и на dye 512², и на dye 128²: velocity в обоих прогонах 128², dye на скорость не пишет.

| | после штриха V1 / V0 | через 3 с V1 / V0 |
| --- | --- | --- |
| `max \|ω\|` внутри | 5.303 / 5.027 | 5.441 / 2.967 |
| `max \|u\|` кольцо 0–1 | 0.0795 / 0.0795 | 0.636 / 0.455 |
| `max \|u\|` тексель 2 | 0.0794 / 0.0796 | 0.620 / 0.453 |
| `Σ\|u\|²` | 5679 / 5378 | 5509 / 3681 |

К 3 с `max|ω|` у V1 держится, у V0 падает. Кольцо рамки и тексель 2 у V1 к 3 с выше V0 (0.636 против 0.455 и 0.620 против 0.453). Сразу после штриха они совпадают. Это находка по логу, не стоп и не вердикт «торнадо»: рост есть и на маске, и на третьем текселе.

Окна `±radius` четырёх ранних точек сразу после штриха, V1 / V0. Dye 512²: `y=0.25` 0.810 / 0.811, `0.35` 0.909 / 0.909, `0.5` 0.917 / 0.917, `0.65` 0.920 / 0.920. Dye 128²: 0.560 / 0.563, 0.845 / 0.843, 0.878 / 0.878, 0.878 / 0.878.

Dye 512², прогон N: пик на оси V1 `y=0.35` 0.899, `y=0.65` 0.917. FWHM поперёк `y=0.5`: после штриха V1 = V0 = 1.0625; через 3 с V1 0.1875, V0 0.3125.

`elapsedMs/N=0.563`, `N=8`, `timer=cpu_driver_not_gpu`, цепочка из 12 пассов, рядом с F3.1 `0.373`. Порога нет ([Techdebt 8k](../last/Techdebt.md)).

### Последствия

- (+) Дифф минимальный: один пресет, три теста, ни один существующий пасс и ассет не меняется.
- (+) Единственная переменная — VC на принятой цепочке F3.1; результат читается однозначно.
- (−) VC работает на velocity 128²; его влияние на нить 512² косвенное, через `AdvectScalar` с cross-res чтением.
- (−) Velocity затухает быстро: эффект VC может быть коротким по времени.
- (−) +1 пасс в цепочке (12 против 11).

**Вне скоупа документа:** E2/E3/E4, F3.2, F3.3, подбор итогового `ε`.
