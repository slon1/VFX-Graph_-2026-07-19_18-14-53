## ADR-010: LUT Palette + HDR Intensity for Field Debug Quad

**Статус:** Принято  
**Дата:** 2026-08-08  
**Контекст:** M3D Framework, Milestone 2d (рендер)

### Контекст

`FieldDebug.shader` (единый шейдер, обслуживающий все `Debug Field Quads` через `FieldDebugQuadsBinder`) сейчас: (а) хардкодит палитру `ScalarHeatmap`-режима как процедурную формулу `float3(d, d*0.4, d*0.08)`, без возможности настройки художником; (б) единственный параметр яркости (`_Scale`) одновременно управляет и цветом, и альфой — нельзя независимо "поджечь" яркость для Bloom, не сделав тексель полностью непрозрачным.

Цель — дать художнику палитру через `Gradient` в инспекторе (не код) и отдельный HDR-множитель, специально для срабатывания URP Bloom (Volume post-processing, настраиваемый пользователем самостоятельно, вне скоупа этого тикета).

### Решение

- **LUT через `Gradient`** (не raw `Texture2D`) в инспекторе `DebugFieldQuadSlot` — печётся в маленькую `Texture2D` (например, `256×1`) один раз при `Setup()` биндера, не каждый кадр. `Gradient` — уже привычный, editor-friendly Unity-виджет (color stops с интерполяцией), не требует внешнего создания текстур художником.
- **LUT — только для `ScalarHeatmap`**, не для `VectorRg` в этом тикете. `VectorRg` (направление→hue, длина→яркость) остаётся как есть — палитра там имеет другой смысл (не "температура", а "направление"), расширение вне скоупа.
- **Разделение `_Scale` (нормализация под LUT + альфа) и нового `_HdrIntensity`** (множитель поверх LUT-цвета, может быть `>1`, не влияет на альфу) — устраняет текущую путаницу одного параметра с двумя ролями.
- **`saturate()` перед LUT-сэмплом** — `d = saturate(rawValue * _Scale)`, чтобы UV LUT-сэмпла всегда был в валидном `[0,1]`, независимо от диапазона реальных значений поля.

### Последствия

Не требует HDR/Bloom-настройки — это делает сам пользователь через URP Volume (Слой 1, отдельно). Этот тикет только даёт шейдеру **возможность** выйти за `1.0` там, где художник явно об этом попросил (`hdrIntensity>1`), не более того.
