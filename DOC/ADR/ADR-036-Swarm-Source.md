## ADR-036: Источник `SwarmSource` — диски команд

**Статус:** принято, EditMode зелёный (2026-10-03). Стаи на экране нет.
**Дата:** 2026-10-03
**Контекст:** M3D Framework, после P1 [ADR-034](ADR-034-Spatial-Hash-And-Teams.md). План — [`plan-Reynolds-Boids-v2.md`](../plan-Reynolds-Boids-v2.md) §P3. P2 (гистограмма хэша) не открывать: она перед P5. Этот документ — только начальные позиции, курс и `teamId`.
**Не меняет:** хэш, `BuildSpatialHash`, пробники `HashProbe_*`, `TeamProfile`, силу соседей, `HeadingSteer`, палитру, `Boids_mk1`, Physarum, fluid.
**ТЗ:** [`todo-adr-034-p3-swarm-source.md`](../last/todo-adr-034-p3-swarm-source.md)

---

### Контекст

Хэш уже строит снимок `position` / `heading` / `teamId`. Куб пробника заполняет объём равномерно и пишет только `restPosition`. Для стай нужен другой старт: несколько дисков на плоскости XZ, у каждого свой `teamId` и общий курс.

Кинематика (ADR-012) сама обнуляет `velocity` в `ClearVelocity` и задаёт скорость в steer. Источнику начальная скорость не нужна. Её добавит опциональный Ньютон в P9.

`TeamProfile` (радиусы, веса, cruise, цвет) в этот тикет не входит. `teamIndex` на спавне — только номер, который пишется в атрибут. Проверку «номер меньше длины списка команд» делает P4, когда список появится.

### Решение

#### 1. Новый вид источника, старые не сдвигаются

`DataSourceKind.Swarm = 4`. `Cube = 0`, `Mesh = 1`, `Bitmap = 2`, `None = 3` остаются на своих числах. Старые ассеты без поля десериализуются в пустой `SwarmSource` и не меняют `sourceKind`.

`EffectAsset.ResolveSource` возвращает это поле. Инспектор показывает его только при виде Swarm. Иначе список спавнов не виден.

#### 2. Диск и курс

Один `System.Random(seed)` на весь `Setup`. Не `UnityEngine.Random`.

Диск равномерный по площади: `r = radius * sqrt(u)`, угол `v * 2π`, `y = 0`. Центр и курс — `Vector2` на XZ (`y` вектора — это Z мира).

Курс единичный, `heading.y = 0`. `jitterDegrees` — максимальный отклонение в градусах в обе стороны от `initialDirection`. Ноль значит курс ровно по направлению. Нулевое направление заменяется случайным углом на полном круге, jitter к нему не прибавляется.

На каждую частицу ровно три числа из генератора, в порядке ТЗ. Тогда повтор с тем же seed даёт те же буферы, а смена jitter не сдвигает позиции.

#### 3. Что источник пишет

`EnsureCapacity(сумма count)` один раз. При сумме 0 — только это, без `RegisterAttribute`: буфер нулевой ёмкости создать нельзя.

Иначе пишет `restPosition`, `heading`, `teamId`. `position` не пишет: мир копирует rest в position в `InitializePositionFromRest`. `velocity` не регистрирует: нули поставит `AutoRegisterAttributes`, если какой-нибудь пасс его читает.

Порядок частиц — порядок спавнов в списке. Два спавна с одним `teamIndex` разрешены.

### Отклонённые варианты

**Решётка внутри диска.** План v2 её отклонил: регулярная сетка видна в силе соседей. Rivalry спавнит `count` точек в круге.

**Начальная скорость.** Кинематическая цепочка её затирает. Писать её сейчас значит второй смысл `velocity` до P9.

**Список `teams` и проверка радиуса против ячейки хэша.** Это P4. Здесь номера команд ещё не с чем сверять.

**Пресет и меню.** Картинку стаи не из чего собрать: нет силы и steer по командам. Гейт P3 — EditMode.

### Последствия

- (+) Спавн команд можно наполнить и проверить без хэша и без GPU-силы.
- (+) Куб, mesh, bitmap и None не меняют смысл.
- (−) Два диска на экране ещё не стая. До P5 они просто разъедутся тем курсом, который им дали, если в эффекте есть steer.
