# M3D Framework — резюме для переноса в новый чат

**Дата среза:** 2026-08-03

## Что это за проект

Unity-фреймворк для GPU-симуляций гибридного типа (поля + частицы), вдохновлён Magic Fluids. Цель эволюционировала за время работы:

1. Началось с research-идеи "коллективный интеллект дронов через поля" — отклонено как слишком широкое и требующее строгой метрики/аналитики, которую автор явно не хочет.
2. Затем — "долгоиграющая, не затухающая fluid-система + boids для поддержания жизни" — уточнено: "незатухающая" физически некорректная цель, правильная формулировка — **прод длённая метастабильность** (vorticity confinement, multi-timescale coupling), не буквальное отсутствие decay.
3. **Финальная формулировка (текущая, актуальная):** удобный фреймворк для быстрого перебора разных алгоритмов взаимодействия частиц и полей (boids, curl noise, Gray-Scott/reaction-diffusion, Lenia-подобные системы, particle-life), цель — найти "завораживающую" визуализацию методом проб, без формальных метрик и аналитики. Автор explicitно не знает заранее, что именно завораживает — инструмент для исследования, не для доказательства гипотезы.

Ключевой принцип домена: поля = память мира (медленно меняются, диффузия/decay), частицы = активные элементы (быстрая динамика) — двусторонний G2P/P2G coupling между ними.

## Архитектурные принципы (стабильны с самого начала)

- Data-driven ping-pong swap полей через `FieldRequest.Access` (Read / WriteInPlace / WritePingPong) — `SimulationWorld` не знает о доменной семантике конкретных эффектов.
- Один `CommandBuffer` на кадр, один `Graphics.ExecuteCommandBuffer` — минимизация driver overhead, целевой бюджет ~10-20 диспатчей/кадр.
- Ноль незапланированных аллокаций в кадре (`FieldRequestSets.Single`, `FieldAccumRequestSets.Single` — кэширование запросов).
- Mobile-first (Android Vulkan / iOS Metal целевые платформы) — жёсткие ограничения: нет float-атомиков на GPU, TBDR-специфика (graphics-path операции вроде `ClearRenderTarget` дороже на тайловых архитектурах).
- `EffectAsset` = пресет (как патч синтезатора) — поведение эмерджентно/хаотично, не скриптуется, только настраивается через параметры и композицию пассов.
- Систематическая валидация лучше точечных патчей — паттерн, повторявшийся многократно (exact-channel validation, generic field slot naming, state machine для P2G).

## Ключевые архитектурные решения (ADR), которые видны только через историю обсуждения

### P2G scatter (частица → поле), ADR-001/002

- Float-атомики недоступны на мобильных GPU → промежуточный `uint`-буфер, fixed-point encode (`(value+Bias)*Scale`), NaN-guard перед cast, отдельный normalize-пасс.
- Replace vs Accumulate-onto-decaying семантика получается **композицией пассов** (наличие/отсутствие `ClearFieldPass` перед P2G), не веткой в коде — архитектурный тезис, подтверждённый на практике (`AgentFieldEcho` = accumulate, `AgentFieldDensity` = replace).
- State machine для валидации порядка Clear→Scatter→Normalize (`Unclear→Cleared→Scattered→(Normalize)→Unclear`) — ловит multi-round ошибки конфигурации на Build.
- Average-decode (velocity) vs sum-decode (density) — разные физические смыслы, sum — осознанное **локальное** исключение из общего average-канона, не пересмотр решения.

### Generic field slot naming, ADR-003

- HLSL-переменные именуются фиксированно (`FieldRead`/`FieldWrite`), не по имени поля — иначе каждое новое поле требует копии кернела. Найдено постфактум как реальный баг (`NormalizeVelocityAccumPass` тихо ломался при смене `fieldName` в инспекторе).
- Multi-field-per-kernel (несколько разных полей в одном dispatch, нужно для Gray-Scott U+V) — явно отложено на M2c, не путать с этим решением.

### Gradient sample, ADR-004

- Категория Force (не Transport, в отличие от `SampleVelocityFieldPass`) — физически это `∇U`, требует `*dt` при интеграции.
- **Критично:** `SimShaderIds.DeltaTime` обязателен в `SetParams`, иначе `dt` в HLSL — мусор/ноль без единой ошибки (реальная находка Grok'а).
- UV-градиент, не физический `∇` (без деления на `FieldSize`) — Strength калибрует масштаб, достаточно для художественного инструмента.
- Известное ограничение (не баг): без Diffuse градиент между далёкими пиками density ≈0 в midpoint (central-diff видит только локальный перепад) — эмпирически подтверждено численным тестом, прямое обоснование приоритета M2b.3.

## Технические уроки, которые стоит помнить при продолжении

1. **`CopyRest` каждый кадр сбрасывает position** — несовместим с velocity-интеграцией (free-roaming агенты). Баг найден на `AgentFieldDensity` (исправлен), **не исправлен на `AgentFieldEcho`/`AgentFieldEcho 1`** (подтверждено при последнем ревью репозитория — открытый долг).
2. **Nearest-cell P2G deposit резонирует с регулярной решёткой частиц** — даёт анизотропные артефакты ("снежинка" вместо гладкого коллапса) при точном совпадении шага решётки частиц и текселя поля. Паллиатив — CurlNoise + грубое разрешение поля; полное решение — Diffuse (M2b.3) или билинейный splat.
3. **Thread group dispatch overflow** при `ParticleCount > ~4.19M` (порог `65535 групп × 64 потока`) — системная уязвимость всех 1D-диспетчинг пассов, не только тестового сценария. Не исправлено, в бэклоге.
4. Reflection Probe периодические GPU-спайки в Profiler — не связаны с симуляцией, косметика рендера, частично снижены (`Source: Custom`), не до конца долечено, осознанно отложено пользователем.
5. Мобильный тест (Samsung S10, Vulkan) подтвердил: **compute-пайплайн (P2G/Gradient/Density) не является узким местом** — просадка FPS (<10) была вызвана VFX Graph рендером 1M частиц, не симуляцией. После отключения VFX-рендера — честные 60 FPS (упор в vsync).
6. Был краш через несколько минут работы на устройстве — причина не расследована до конца (вероятная гипотеза — тепловой троттлинг, не подтверждена реальным crash-логом).
7. Методология тестирования, которая хорошо себя показала: контроль на state machine багов ловится численным MCP-readback тестом лучше, чем визуальной проверкой (пример — Gradient/Density численные smoke-тесты с точными числами, а не "выглядит нормально").
