# M3D Framework — резюме для нового чата (тонкая настройка боидов)

**Дата среза:** 2026-08-08 (продолжение предыдущего среза от 2026-08-03 — см. `ProjectSummary.md`, если он тоже передан; здесь только то, что произошло после)

## Контекст этого перехода

Основной архитектурный чат довёл фреймворк до состояния "полный словарь примитивов + первый реальный творческий результат (Gray-Scott + boids)". Пользователь хочет теперь заняться **тонкой визуальной настройкой** поведения боидов (не нравится текущий вид, есть референс на гите, к чему хочет приблизиться) — это другой режим работы (быстрая итерация параметров, не архитектурные ADR-циклы), поэтому вынесено в отдельный чат. Git и документация переданы отдельно пользователем.

## Ключевые находки/уроки из этой части разговора

1. **CFL-нестабильность Gray-Scott на мобильном (checkerboard-артефакт)** — реальный, не гипотетический баг, пойман на устройстве. Причина: `deltaTime = Time.deltaTime * SimulationSpeed` вычисляется один раз в `SimulationWorld.Update()`, **не делится на N** при нескольких повторах `GrayScottPass` за кадр. При низком FPS устройства (телефон ~60 FPS против ~120-200 в редакторе) тот же `SimulationSpeed` даёт кратно больший `dt`, легко пробивающий CFL-порог (`Du·dt ≲ 0.25`). Рабочий обходной путь пользователя: `Speed<50` + `2×GrayScott` вместо `3×`. **Не исправлено в коде** — рекомендованный системный фикс: clamp `deltaTime` в `SimulationWorld.Update()` (не делить `dt/N` внутри пасса — архитектурно неудобно, пасс не знает о своей кратности в списке). Подробный разбор в `DOC/last/Techdebt.md`.
2. **`InputRouter` баг** — mouse drag по числовому полю в инспекторе (стандартный Unity-жест изменения значения) засчитывается как валидный тач/клик, потому что `CollectPointers()` не проверяет, что курсор физически над Game View. Editor-only, не проявится в билде на устройстве. Не исправлено.
3. **Возможный Rebuild-триггер от простого наведения мыши** — пользователь наблюдал "узоры резко пропадают и вырастают заново в тех же местах" при активном движении мыши между полями пассов в инспекторе. Гипотеза (Grok): просадка `dt` от тяжёлого GUI-repaint. Альтернативная гипотеза (Claude): полный `Rebuild()`, сбрасывающий `hasFired`/`ClearValue`. **Не подтверждено окончательно** — рекомендован дешёвый `Debug.Log` в `Build()` для проверки, не сделан.
4. **"Точка на поле отстаёт от частицы"** — визуально подтверждено пользователем (зелёные линии на скриншоте). Проверено кодом и исключено: (а) текстура quad'а не устаревает — `Execute()` каждый кадр берёт свежий `field.Current`; (б) порядок `SimulationWorld.Update()` корректен — все пассы+swap полностью происходят до `Graphics.ExecuteCommandBuffer`, биндеры вызываются после. Вероятный оставшийся кандидат — собственная внутренняя задержка рендера **VFX Graph** (внешняя система, не M3D-код). Рекомендован тест: покадровый Step, сравнить оффсет у медленной vs быстрой частицы (пропорционален скорости → задержка на кадр; одинаков у всех → координатный баг). **Результат теста не получен** до конца этой сессии.
5. **VFX Graph — подтверждённо главный источник просадки FPS на мобильном** (ещё с самого первого мобильного теста: отключение VFX-рендера подняло FPS с <10 до 60 без единого изменения в compute). Переход на `RenderMeshIndirect`/`RenderMeshInstanced` — повышенный приоритет техдолга, не сделан. Вероятно, заодно уберёт и находку №4 (устранит VFX-специфичную задержку).

## Текущие boids-эффекты в репозитории

- **`Boids_mk1.asset`** — три независимых field-петли (Alignment через `flockVel`/velocity-P2G; Cohesion через `cohesionDensity`, грубое разрешение + `Diffuse×6`; Separation через `separationDensity`, мелкое разрешение, без Diffuse), четыре силы на G2P (`Sample Velocity Field` + 2× `Sample Gradient Field`), плюс `Curl Noise` как базовый "+noise"-член. `CopyRest` отсутствует (баг закрыт).
- **`Gray-Scott-Boids.asset`** — тот же boids-контур + `agentPresence`-петля (Replace) + `Seed→GrayScott→AgentBoost/Erode→TouchInjectGrayScott`. Пользователь пробовал добавлять вручную четвёртую G2P-силу (избегание высокого V через `Sample Gradient Field` с отрицательным `Strength`) — результат "слишком хаотично", не закоммичено.
- **`Gray-Scott-Agents.asset`** — контрольный вариант, агенты пишут в GS, но не читают field обратно в движение (чистое "one-way" сравнение).

## Известное наблюдение пользователя, которое стоит держать в уме

Текущее движение боидов ощущается как "полотно" — вероятная причина: `CurlNoiseForce` (гладкий, пространственно когерентный шум) как базовый источник движения. Обсуждали два направления фикса: (а) бесплатно — поднять `Frequency` на существующем Curl Noise; (б) добавить per-particle jitter, не завязанный на позицию (единственный способ гарантированно убрать пространственную корреляцию — смена алгоритма шума Value→Perlin **не** решит это, оба дают тот же класс когерентности). Не реализовано, пользователь ещё не выбрал направление.

## Рабочий процесс (для нового чата)

Тот же паттерн, что использовался весь проект: Claude — архитектурный ревьюер, Grok (через Cursor) — исполнитель. Для чисто параметрической настройки (крутить `Strength`/`Amplitude`/`Frequency` в инспекторе) Grok не нужен вообще — пользователь может делать это сам, Claude — консультирует по физике/интерпретации результата. Grok нужен только если понадобится новый тип силы/пасса, отсутствующий в текущем словаре.
