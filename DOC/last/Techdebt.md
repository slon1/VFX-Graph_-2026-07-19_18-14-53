## Группа A — стабильность мобильного тестирования

Стоит закрыть раньше остального: мешает надёжности дальнейших прогонов на устройстве.

1. **`Releasing render texture that is set to be RenderTexture.active!`** — предупреждение на Android при pause/resume (сворачивание приложения). Вероятно, неполная обработка потери/восстановления surface в `FieldSet`/`SimulationWorld`. Не блокировало текущий тест, но стоит проверить перед тем, как полагаться на длинные мобильные сессии в будущем.

1b. **`deltaTime` clamp в `SimulationWorld` (CFL / Gray-Scott «шахматы» на мобиле).**  
   **Приоритет:** низкий — отдельная маленькая задача, не срочная; зафиксировать, чтобы не потерять разбор.  
   **Решение (согласовано):** clamp сырого/масштабированного `deltaTime` в World, **не** «делить `dt` на N внутри `GrayScottPass`».

   **Механика сейчас** (`SimulationWorld.Update`):

   ```csharp
   float deltaTime = Time.deltaTime * effect.SimulationSpeed; // ~строка 62
   // … каждый enabled pass.Execute(context, deltaTime) — полный dt, не dt/N
   ```

   Gray-Scott (и Diffuse): явный 5-point Laplacian, `new = old + DeltaTime * (Du·∇² + …)`, Du≈0.16.  
   CFL-ориентир: `Du·dt ≲ 0.2–0.25` → **безопасный dt на один React ≲ ~1.2–1.5**.  
   `saturate` на выходе GS — clamp концентраций в [0,1], **не** замена CFL (ADR-009).

   **Арифметика «один Speed — разный мир»:**

   | Условие | FPS | Speed | dt на React | Du·dt | 3× GrayScott |
   | --- | --- | --- | --- | --- | --- |
   | Desktop / Editor | ~120–200 | 100 | ~0.5–0.8 | ~0.08–0.13 | обычно ок |
   | Mobile | ~30–45 | 100 | ~2.2–3.3 | **~0.35–0.53** | шахматы за 1–2 с |
   | Mobile (рабочие) | ~30 | <50 | ~1.7 | ~0.27 | на грани; 2× React терпимее |

   Симптом срыва: **шахматная доска** (Nyquist / odd-even мода дискретного Laplacian). На десктопе высокий FPS маскирует большой `SimulationSpeed`; на мобиле тот же Speed даёт шаг выше устойчивости.

   **Связь с «старыми» крашами / кашей кадра:** любой hitch раздувает один `Time.deltaTime` (спайк Reflection Probe — п.6; hover Inspector в Play; GC; VFX stall на мобиле; pause/resume). При Speed≫1 этот кадр мгновенно нарушает CFL → визуальный взрыв / каша, который раньше можно было списать на «рандомный краш шейдера» или тач. Один clamp (`Mathf.Min(Time.deltaTime, maxDt) * Speed` или clamp уже после Speed) режет хвост распределения dt для **всех** dt-пассов сразу.

   **Почему не dt/N в пассе:** N — композиция EffectAsset (сколько копий React в списке), не свойство численной схемы; деление спрятало бы баг конфигурации и разъехалось бы с Diffuse/Decay/Integrate, у которых тот же World-`dt`. Clamp в World — одна точка правды, калибровка Speed остаётся осмысленной относительно «симулированных секунд», а FPS-спайки не пробивают CFL.

   **DoD будущего фикса (черновик):** serialized `maxDeltaTime` (или `maxSimDeltaTime` после Speed) на `SimulationWorld` / EffectAsset; default подобрать под Du=0.16 и типичный N; док-строка в getting-started / pass-catalog; smoke: искусственно большой `deltaTime` не даёт шахмат на GS.

## Группа B — подтверждённые баги, не полностью закрытые

2. **`CopyRest` ломает свободное блуждание частиц.** Сбрасывает `position = restPosition` каждый кадр — конфликтует с velocity-интеграцией (частицы "дрожат на месте" вместо движения). Найдено и исправлено на `AgentFieldDensity`, но **не подтверждено**, что `AgentFieldEcho` (собирался по идентичной изначальной спецификации пайплайна) не страдает тем же багом. Нужно явно перепроверить и убрать `CopyRest` там же, если баг подтвердится.

3. **Thread group dispatch overflow.** При `ParticleCount` выше ~4.19M (`Cube Resolution ≥ 162`) любой 1D-диспетчинг (`groups = ceil(count/64)`) падает с `Thread group count is above the maximum allowed limit (65535)`. Затрагивает **все** `ParticleKernelPass`-наследники и `ScatterVelocityToFieldPass`, не только тестовый сценарий, где было найдено. Фикс: переход на 2D-grid dispatch (`groupsX/groupsY`, `groupsX = min(totalGroups, 65535)`, `groupsY = ceil(totalGroups/groupsX)`) с соответствующей правкой вычисления линейного индекса частицы в HLSL (`id.x + id.y * groupsX * THREADS` вместо голого `id.x`). Общий helper на C#-стороне + общий паттерн в шейдерах, не точечный патч под один кернел.

## Группа C — известные ограничения (задокументированы, осознанно отложены)

4. **Нет `ClampFieldPass`.** Аналог `SpeedLimitPass` для частиц, но для полей. Сейчас есть только частичный inline-clamp (`MaxFieldSpeed`) внутри `TouchInjectVelocityFieldPass`, не переиспользуемый отдельный пасс, применимый после любых операций с любым полем.

6. **Reflection Probe периодические спайки в Profiler.** `Environment Reflections → Source: Custom` снизил среднюю стоимость (с ~62 мс до ~0.1 мс на кадр), но пики в таймлайне всё ещё видны через равные интервалы, источник до конца не подтверждён. Вероятная причина — Lit-материал debug-quad'а сэмплирует environment reflections. Рекомендованный фикс: перевести материал quad'а на Unlit-шейдер.

7. **`CubeSource` — предположительно синхронная генерация частиц на CPU.** Вероятная причина фриза 2-3 сек на старте при большом `Resolution`. Не подтверждено профилированием, но станет блокером для M2f (reroll без рестарта), если подтвердится — стоит проверить перед тем, как браться за M2f.

8. **Мёртвый null-coalescing branch** в конструкторе `SimContext` (`fields ?? new FieldSet()`). `SimulationWorld.Build` всегда передаёт non-null `FieldSet` — упростить до `ArgumentNullException`/убрать оператор, не маскировать потенциальную ошибку сборки.

## Группа D — roadmap-пункты с повышенным приоритетом по итогам тестов

9. **Переход с VFX Graph на `RenderMeshIndirect`/`RenderMeshInstanced`.** Изначально часть M2d ("рендер"), теперь — подтверждённая причина основной просадки FPS на мобильном устройстве (Samsung S10, Vulkan): отключение только VFX-рендера частиц подняло FPS с <10 до 60 (упор в vsync), без единого изменения в compute-пассах. Приоритет этого пункта стоит поднять, не дожидаясь естественной очереди roadmap. Открытый вопрос перед стартом: деградация от VFX-инфраструктурного оверхеда или от чистого overdraw/fill-rate большого количества частиц — стоит проверить через снижение particle count в текущем VFX-сетапе перед переписыванием рендера, это откалибрует ожидания от перехода.

10. **LUT-палитра + trail/persistence buffer** (M2d, часть "живого" визуального рендера). Не срочно само по себе, но логично объединить с пунктом 9 в одну задачу, если переписывается рендер-слой целиком.

## Группа E — крупные архитектурные решения (не начинать без явного триггера)

11. **Spatial hash.** Сознательно не начинать, пока Tier 1 (density-field flocking через уже готовый P2G) не окажется явно недостаточным на практике — не хватает точных контактов между частицами (sand/SPH-подобные сценарии). Критерий запуска уже согласован в предыдущих обсуждениях.

12. **Унификация `ParticleSet`/`FieldSet`/будущего `SpatialHashSet`.** Решение отложено до появления spatial hash как третьего типа ресурса — сам факт его появления должен показать, какая общая абстракция реально нужна. Не начинать раньше пункта 11.

13. **Emitters / dead-pool модель** (`alive`/`age` builtin-атрибуты + `CompactAndSpawnPass`). Нужны для реализации "тач создаёт новые частицы" — не реализовано. Актуализируется, когда дойдём именно до этой фичи.

14. **`PassGroup`/`SolverPreset`** (M2e). Для комбинирования "семей алгоритмов" (fluid, Gray-Scott, Lenia, particle-life) одним элементом вместо ручной пересборки списка пассов. Gray-Scott уже есть (M2c.1) — триггер «несколько семей одновременно» становится актуальнее по мере появления Lenia/fluid.

15. **Reroll + Play-Mode snapshot-to-preset** (M2f). UX для быстрого перебора параметров без потери находок и без рестарта. Не блокирует текущую техническую работу — см. также пункт 7 (возможный блокер CubeSource).

16. **Эвристика "интересности"** (M2h, опционально). Только если ручной перебор параметров реально станет узким местом на практике — не аналитика, не метрика, просто ускоритель поиска.

## Как пользоваться этим списком

- **Группа A/B** — короткая, самостоятельная техническая сессия с исполнителем, не требует архитектурных решений.
- **Группа C** — известные ограничения; закрывать по мере касания соседнего кода.
- **Группа D** — рассмотреть отдельно, приоритет уже подтверждён тестами, но объём работы сопоставим с отдельным roadmap-шагом, не с мелким фиксом.
- **Группа E** — не трогать, пока не сработает явно описанный триггер у каждого пункта.
