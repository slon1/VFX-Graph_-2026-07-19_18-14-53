# TechDebt.md — накопленный технический бэклог

**Дата создания:** 2026-08-03 **Контекст:** накоплено за M2a / M2a.1 / M2b.1 / M2b.1.1, зафиксировано после первого мобильного теста (Samsung S10, Vulkan)

Этот документ — рабочий список отложенных задач: реальных багов, известных ограничений и roadmap-пунктов, приоритет которых изменился по итогам тестирования. Не всё здесь срочно — приоритет и группа явно указаны при каждом пункте.

---

## Группа A — стабильность мобильного тестирования

Стоит закрыть раньше остального: мешает надёжности дальнейших прогонов на устройстве.

1. **`Releasing render texture that is set to be RenderTexture.active!`** — предупреждение на Android при pause/resume (сворачивание приложения). Вероятно, неполная обработка потери/восстановления surface в `FieldSet`/`SimulationWorld`. Не блокировало текущий тест, но стоит проверить перед тем, как полагаться на длинные мобильные сессии в будущем.

## Группа B — подтверждённые баги, не полностью закрытые

2. **`CopyRest` ломает свободное блуждание частиц.** Сбрасывает `position = restPosition` каждый кадр — конфликтует с velocity-интеграцией (частицы "дрожат на месте" вместо движения). Найдено и исправлено на `AgentFieldDensity`, но **не подтверждено**, что `AgentFieldEcho` (собирался по идентичной изначальной спецификации пайплайна) не страдает тем же багом. Нужно явно перепроверить и убрать `CopyRest` там же, если баг подтвердится.

3. **Thread group dispatch overflow.** При `ParticleCount` выше ~4.19M (`Cube Resolution ≥ 162`) любой 1D-диспетчинг (`groups = ceil(count/64)`) падает с `Thread group count is above the maximum allowed limit (65535)`. Затрагивает **все** `ParticleKernelPass`-наследники и `ScatterVelocityToFieldPass`, не только тестовый сценарий, где было найдено. Фикс: переход на 2D-grid dispatch (`groupsX/groupsY`, `groupsX = min(totalGroups, 65535)`, `groupsY = ceil(totalGroups/groupsX)`) с соответствующей правкой вычисления линейного индекса частицы в HLSL (`id.x + id.y * groupsX * THREADS` вместо голого `id.x`). Общий helper на C#-стороне + общий паттерн в шейдерах, не точечный патч под один кернел.

## Группа C — известные ограничения (задокументированы, осознанно отложены)

4. **Нет `ClampFieldPass`.** Аналог `SpeedLimitPass` для частиц, но для полей. Сейчас есть только частичный inline-clamp (`MaxFieldSpeed`) внутри `TouchInjectVelocityFieldPass`, не переиспользуемый отдельный пасс, применимый после любых операций с любым полем.

5. **Имя сэмплера `sampler_linear_clamp`** в `FieldPasses.compute` не соответствует конвенции implicit-семплеров Unity (правильный паттерн — `linear_clamp_sampler`). Не проверено на реальном устройстве — потенциально тихо неверная (не билинейная) фильтрация вместо ошибки компиляции.

6. **Reflection Probe периодические спайки в Profiler.** `Environment Reflections → Source: Custom` снизил среднюю стоимость (с ~62 мс до ~0.1 мс на кадр), но пики в таймлайне всё ещё видны через равные интервалы, источник до конца не подтверждён. Вероятная причина — Lit-материал debug-quad'а сэмплирует environment reflections. Рекомендованный фикс: перевести материал quad'а на Unlit-шейдер.

7. **Multi-field-per-kernel биндинг** — явно отложено на M2c (см. ADR-003). Понадобится для Gray-Scott (U+V в одном dispatch) — index/role-based именование текстурных слотов вместо текущего единственного generic `FieldRead`/`FieldWrite` (который по конструкции поддерживает ровно одно уникальное имя поля на kernel).

8. **`CubeSource` — предположительно синхронная генерация частиц на CPU.** Вероятная причина фриза 2-3 сек на старте при большом `Resolution`. Не подтверждено профилированием, но станет блокером для M2f (reroll без рестарта), если подтвердится — стоит проверить перед тем, как браться за M2f.

9. **Мёртвый null-coalescing branch** в конструкторе `SimContext` (`fields ?? new FieldSet()`). `SimulationWorld.Build` всегда передаёт non-null `FieldSet` — упростить до `ArgumentNullException`/убрать оператор, не маскировать потенциальную ошибку сборки.

## Группа D — roadmap-пункты с повышенным приоритетом по итогам тестов

10. **Переход с VFX Graph на `RenderMeshIndirect`/`RenderMeshInstanced`.** Изначально часть M2d ("рендер"), теперь — подтверждённая причина основной просадки FPS на мобильном устройстве (Samsung S10, Vulkan): отключение только VFX-рендера частиц подняло FPS с <10 до 60 (упор в vsync), без единого изменения в compute-пассах. Приоритет этого пункта стоит поднять, не дожидаясь естественной очереди roadmap. Открытый вопрос перед стартом: деградация от VFX-инфраструктурного оверхеда или от чистого overdraw/fill-rate большого количества частиц — стоит проверить через снижение particle count в текущем VFX-сетапе перед переписыванием рендера, это откалибрует ожидания от перехода.

11. **LUT-палитра + trail/persistence buffer** (M2d, часть "живого" визуального рендера). Не срочно само по себе, но логично объединить с пунктом 10 в одну задачу, если переписывается рендер-слой целиком.

## Группа E — крупные архитектурные решения (не начинать без явного триггера)

12. **Spatial hash.** Сознательно не начинать, пока Tier 1 (density-field flocking через уже готовый P2G) не окажется явно недостаточным на практике — не хватает точных контактов между частицами (sand/SPH-подобные сценарии). Критерий запуска уже согласован в предыдущих обсуждениях.

13. **Унификация `ParticleSet`/`FieldSet`/будущего `SpatialHashSet`.** Решение отложено до появления spatial hash как третьего типа ресурса — сам факт его появления должен показать, какая общая абстракция реально нужна. Не начинать раньше пункта 12.

14. **Emitters / dead-pool модель** (`alive`/`age` builtin-атрибуты + `CompactAndSpawnPass`). Нужны для реализации "тач создаёт новые частицы" — не реализовано. Актуализируется, когда дойдём именно до этой фичи.

15. **`PassGroup`/`SolverPreset`** (M2e). Для комбинирования "семей алгоритмов" (fluid, Gray-Scott, Lenia, particle-life) одним элементом вместо ручной пересборки списка пассов. Актуализируется вместе или после появления Gray-Scott/Lenia, когда реально появится больше одной независимой семьи алгоритмов одновременно.

16. **Reroll + Play-Mode snapshot-to-preset** (M2f). UX для быстрого перебора параметров без потери находок и без рестарта. Не блокирует текущую техническую работу — см. также пункт 8 (возможный блокер).

17. **Эвристика "интересности"** (M2h, опционально). Только если ручной перебор параметров реально станет узким местом на практике — не аналитика, не метрика, просто ускоритель поиска.

## Как пользоваться этим списком

- **Группа A/B** — короткая, самостоятельная техническая сессия с исполнителем, не требует архитектурных решений.
- **Группа C** — можно копить и закрывать пачкой перед стартом M2c (который и так требует ревизии multi-field механики — логично почистить остальное заодно).
- **Группа D** — рассмотреть отдельно, приоритет уже подтверждён тестами, но объём работы сопоставим с отдельным roadmap-шагом, не с мелким фиксом.
- **Группа E** — не трогать, пока не сработает явно описанный триггер у каждого пункта.
