## 1. Что известно о 48 в проекте (проверено ревью)

- Значение по умолчанию живёт в одном месте: `Assets/Scripts/Passes/BoidsPasses.cs`, строка `[SerializeField] private int maxNeighbors = 48;` (строка 34). Свойство `MaxNeighbors` требует значение не меньше 0. `BoidNeighborForcePass` обычный класс, не `ScriptableObject`.
- **Все 12 существующих эффектов хранят `maxNeighbors: 48` в самом ассете явно**: `Boids_hash`, `Boids_hash100k`, `Boids_hash100k_x4`, `Boids_hash200k`, `Boids_hash200k_points`, `Boids_hash30k`, `Boids_hash400k`, `Boids_hash400k_2teams`, `Boids_hash600k`, `Boids_hash800k`, `Boids_hash_2teams`, `Boids_hash_points`. Unity берёт для них сериализованное 48, а не инициализатор поля, поэтому смена поля по умолчанию их **не меняет**.
- **На `feature/reynolds-boids` пас создают ровно два билдера, оба это старые пресеты и оба ставят 48 явно (на `feature/classic-boids` добавлен третий, `CreateBoidsHashClassicAsset`, тоже с явным 48, см. §4):** `CreateBoidsHashAsset` (меню `Tools/M3D/Create Boids Hash Effect`, строка около 1994) и `CreateBoidsHashTwoTeamsAsset` (меню `Tools/M3D/Create Boids Hash 2 Teams Effect`, около 2125). Тесты `BoidsHashPresetTests` (строка 254) и `BoidsHashTwoTeamsPresetTests` (строка 86) проверяют 48 на загруженных ассетах. **Намерение владельца: эти два меню остаются на 48.** Остальные 10 ассетов в коде не создаются, их делают дублированием, а дубликат наследует сериализованное 48. Значит, инициализатор 128 действует только на пас, добавленный с нуля (`new BoidNeighborForcePass()`, добавление пасса в инспекторе, будущий новый билдер без явного `MaxNeighbors`); в дубликате старого пресета значение ставят вручную. Это записывается в последствия ADR-056.
- Тесты, которые создают пас без `MaxNeighbors` и поэтому зависят от значения по умолчанию неявно: `BoidNeighborForcePackedTests` (640), `BoidNeighborForceRepeatTests` (237), `BoidNeighborForceSortedTests` (422, 551), `BoidNeighborForceTests` (191, 292, 345, 434, 764), `PerfArgsTests` (419). Ни один не проверяет значение по умолчанию; поведение в сценах из нескольких частиц от капа не зависит, пока посещённых слотов не больше 48.
- Скрипты серий `Tools/s10/run-series.ps1` (`$maxNeighbors = 48`) и `capture-streamline.ps1` (`$maxNeighborsText = "48"`) **всегда передают `-m3d_maxn`**, то есть значение ассета не используют. Кнопка `MaxN 48` на экране `FPSDisplay` задаёт 48 во время работы.

## 4. Фаза Б. Документы (один коммит)

1. **Новый `DOC/ADR/ADR-056-Default-MaxNeighbors.md`** (на `feature/classic-boids` заняты 054 `Classic-Boids-Tail` и 055 `Swarm-Spring-Force`; 044 зарезервирован под P8; перед созданием проверить `ls DOC/ADR`). Статус «предварительно». Содержание:
   - **Решение:** значение по умолчанию поля `BoidNeighborForcePass.maxNeighbors` 128 для новых пресетов; 12 существующих ассетов и билдеры старых пресетов остаются на 48 ради совместимости с тестами.
   - **Почему 128 (честно):** это **временная цена**, а не принятая картинка. Play (F5.2) принял только кап 192, кап 128 не принят. Кап 192 на S200 не проходит M1: кадр режима B 36,01 мс и 126,79 цикла на частицу при полосе M2 45–58, с рендером 40,10 мс (около 25 кадров/с). Кап 128 даёт 24,86 мс без рендера. Владелец по наблюдению на больших скоплениях (400 000 частиц) считает, что разница между 48 и 192 на итоговой картинке слабая по сравнению с обходом всех соседей (кап 0); это наблюдение владельца, моделью и измерением не проверено, и оно расходится с отметкой Play для 128.
   - **Цена:** цена обхода растёт линейно с капом, около 0,15 мс на единицу на S200: 6,99 / 18,92 / 28,96 мс для 48 / 128 / 192 (`F5-report.md`).
   - **Оценка кадра для 128 с рендером:** `24,86 + (40,10 − 36,38) = 28,58 мс` (кадр режима B капа 128 плюс стоимость рендера, взятая с капа 192, 3,72 мс). Допущения: рендер стоит одинаково при любом капе, частота около 700 МГц. **Это оценка, не измерение**, захвата для 128 нет.
   - **Что не проверено, прямо:** кап 128 с рендером на S200; устойчивая частота (433 МГц) в этой серии; визуальный вывод основан на Play и наблюдении владельца, не на модели; Play шёл на сценах 3000 и 100k частиц.
   - **Когда пересматривать:** после P8; после проверки ячейки меньше радиуса в CPU-модели (оценка ревью, `DOC/MEASURE/p6-cpu-model/cell_geometry.py`, равномерная плотность, не измерение: при том же числе принятых соседей эквивалентные капы относительно 192 равны 174 / 133 / 115 для пропуска ячеек / ячеек R/2 / R/2 с пропуском, то есть ниже в 1,1 / 1,4 / 1,7 раза); после возврата суммы отталкивания (ADR-053 §3 и §6: сумма держит стаю при `maxNeighbors = 0` и рвёт её вдоль решётки при положительном капе); при появлении данных об устойчивой частоте.
   - **Связь с усреднением отталкивания:** пока отталкивание усредняется (`sep / sepN`), смена капа меняет только выборку соседей, а не масштаб силы. **При сумме масштаб зависел бы от капа примерно в 2,6 раза между 48 и 128**: это оценка ревью (принятых соседей около 35% посещённых, то есть около 17 при капе 48 и около 45 при капе 128, а измеренное отношение цены обхода 128/48 равно 2,71), в ADR-053 такого числа нет, ссылки на ADR-053 для него не давать.
   - **Отвергнутые варианты:** 192 по умолчанию (не проходит M1 на S200); 48 по умолчанию (визуально худший, владелец); один кап для всех сцен навсегда (цена растёт с числом частиц, значение остаётся полем ассета).
   - **Последствия:** инициализатор 128 действует на пас, добавленный с нуля; **дубликат старого пресета наследует 48**, значение в дубликате ставят вручную; два меню старых пресетов остаются на 48 и обязаны дать 48, пока не отменено решение; серии на новых пресетах запускать с `-MaxN 128`, серии на старых без изменений; новый ассет записывает значение явно, поэтому будущая смена поля по умолчанию старые ассеты не заденет.
   - **Билдеры и классические пресеты.** На этой ветке пас создают три билдера, все с явным `MaxNeighbors = 48`: `CreateBoidsHashAsset`, `CreateBoidsHashTwoTeamsAsset` и новый `CreateBoidsHashClassicAsset`. `Boids_hash_classic` и `Boids_hash_classic_points` собраны по рецепту `Boids_hash` для сравнения и остаются на 48 по замыслу; в тест `ExistingEffects_StayAt48` они не входят (его список из 12 имён не менялся). Новый билдер, которому нужны 128, должен задать значение явно или не задавать вовсе.
   - **Отклонение фазы А.** `Boids_hash_2teams.asset` хранил `maxNeighbors: 128` (остаток правок владельца, коммит `147147c`), возвращено 48.    - **Базовое состояние тестов** на `feature/classic-boids`: 467 / 462 / 5 до и 469 / 464 / 5 после; упавшие пять: `Preset_MatchesTwoTeams`, `Chain_ThreeHundredFrames_StaysFiniteInsideBox` (вариант двух команд; вариант одной стаи прошёл), `Preset_IsSwarmCurlOnXZ`, `Preset_MatchesDyeInjectComposition`, `Preset_MatchesDyeInjectVcComposition`.
