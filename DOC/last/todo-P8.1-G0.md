## Что изменилось

Цель 400 000 частиц **отменена** (решение владельца 2026-11-18). Новая цель: **узнать максимальное число частиц на S10 (Mali-G76) для каждого варианта пайплайна**: кап 48 и поле с давлением (K = 3), при постоянной плотности (как P400c) и при фиксированном мире. Критерий по умолчанию: медиана кадра с рендером (режим A) не больше 33,3 мс (30 кадр/с); отдельно считать для 16,7 мс (60 кадр/с) и для кадра без рендера (режим B) не больше 16,7 мс. Замер при 400 000 из В остаётся как верхняя точка. Это ТЗ даёт **базовую линию** для сравнения с будущими оптимизациями (G1: безопасные правки и микробенчмарки; G2: чтение силы через текстуры, сбор через блендинг, round-robin) и устраняет часть неясностей в цифрах В.

**Пайплайн G0:** код (небольшой), сборка владельцем, замеры, отчёт. **Код пасса, шейдеры, формулы не менять**, кроме одной правки гигиены в этапе 2.

## 2. Этап 2. Гигиена повторов давления

В `FieldDensityPressure.cs` обнуление `scratchVelocity` (`cmd.SetBufferData(scratchVelocity, scratchZeros)`) стоит **внутри** цикла повторов, то есть на каждый повтор 4,8 МБ CPU→GPU (400 000 × 12 Б); в `FieldNeighborForcePass` оно один раз перед циклом. Перенести обнуление перед цикл (один раз на `Execute`), как у силы поля. Значения скорости в скрэтче при повторах накапливаются, на результат не влияют (скрэтч никому не читается). Тест: в диагностическом режиме `press` с `fieldrep 4` число вызовов `SetBufferData` на скрэтч-скорость за `Execute` равно 1 (если считать вызовы нечем, достаточно, чтобы тесты давления оставались зелёными, а в отчёте было написано, как проверено). Коммит. Краткий отчёт.
