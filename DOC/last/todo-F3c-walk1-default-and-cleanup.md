# ТЗ F3c: `walk 1` по умолчанию, заморозка `walk 0` и `walk 2`, уборка хвостов F3

**Исполнитель:** Grok (код, тесты, документы). **Проверка на устройстве (S10):** владелец. **Ревью:** Claude.
**Куда положить:** `DOC/last/todo-F3c-walk1-default-and-cleanup.md`. Общие правила §0 действуют.
**Основа:** [ADR-048](../ADR/ADR-048-Default-Walk-Mode.md) (решение владельца 2026-10-19), замеры F3 в [ADR-047](../ADR/ADR-047-Sorted-Order-Neighbor-Walk.md) §6.
**Коммиты:** (А) код, ассеты, тесты; (Б) документы и аудит хвостов. Каждый коммит отдельно, EditMode зелёный в каждом.

## Что закрываем

1. Режим по умолчанию `walkMode = 1` (код, ассеты, тесты).
2. Режимы 0 и 2 заморожены: остаются в коде и тестах, не развиваются, не удаляются.
3. Документы и техдолг согласованы с решением; хвосты найдены, исправлены или оформлены предложением.

**А1. Значение по умолчанию.** `Assets/Scripts/Passes/BoidsPasses.cs`, поле `walkMode` пасса `BoidNeighborForcePass`: `[SerializeField] private int walkMode = 1;`. Допустимые значения 0..2 и исключение `ArgumentOutOfRangeException` не менять. К полю и к свойству `WalkMode` добавить комментарий в одну-две строки: по умолчанию 1, режимы 0 и 2 заморожены (ADR-048). Без `[Obsolete]`, без изменения логики `SelectKernel`, защиты по радиусу, `PackedRequested`, `PackedWritten`, `EffectiveWalkMode`. Файлы `.compute` не трогать, **даже комментарии** (критерий: `git diff` по `Assets/**/*.compute` пуст).

2. В каждом из них задать `WalkMode = 0` явно перед запуском. Числовые ожидания, допуски и сами биты не менять. Перечислить в сдаче каждый такой тест и строку, где добавлен `WalkMode = 0`.

**А4. Новый тест на пресеты** (новый файл в `Assets/Tests/Editor/`, с `.meta`; имя по образцу соседних, например `BoidsHashPresetsWalkDefaultTests.cs`). Перебрать через `AssetDatabase` все эффекты, содержащие `BoidNeighborForcePass` (сейчас десять, имена в код не вшивать). Для каждого:

## Часть В. Проверки

**EditMode (Grok):** зелёный, число до и после (число «до» снять фактическим прогоном перед А1; 370 это значение после F3b), перечень изменённых и новых тестов. Побитовый тест `walk 0` проходит. `git diff` по `*.compute` пуст.

**Play (Grok):** `Boids_Hash` (огонь) и `Boids_Hash_2Teams` без `-m3d_walk`: `EffectiveWalkMode == 1`, предупреждений об откате нет, вид в кадрах около 1 с и 15 с совпадает с видом при `-m3d_walk 0`, как в F3a и F3b.

**Устройство (владелец, один короткий прогон).**
- **Сборка APK: владелец, из коммита Б, не из открытого редактора.** В рабочем дереве сейчас грязные сцены и `Mobile_RPAsset`, из-за них прошлые APK были `dirty=1`. Перед сборкой `git status` чистый и штамп сборки показывает `dirty=0`; иначе отклонение циклов смешается с этими правками. Варианты (выбирает владелец): закоммитить эти правки отдельным коммитом до сборки, убрать их через `git stash`, либо собрать из отдельной рабочей копии (`git worktree add <папка> <хеш коммита Б>`). Grok в сдаче перечисляет грязные файлы и спрашивает, что с ними делать.
- Условия: заряд не ниже 50%, `powersave=0`. Без аргумента `-m3d_walk`: S200 (`Boids_Hash_test200k`), режим B, три повтора и один профиль Streamline режима B.
- Ожидание: в строках `DONE` `walk=1 walkeff=1`; метка `vsync` в сводке (медиана не больше 16,9 мс и разброс не больше 0,1 по трём повторам), ровно 16,7 мс не требуется; циклы на частицу сравнивать с серединой прежнего диапазона 40,2–41,2, то есть с 40,7: порог 5% от неё (от 38,7 до 42,7), один захват. Выход за порог объяснить.
- Результат записать как новую базу «после F3» в `DOC/MEASURE/` и в строку README (Б3). Повтор Замера 4 (тепловой режим) в это ТЗ не входит, отдельное решение владельца.
