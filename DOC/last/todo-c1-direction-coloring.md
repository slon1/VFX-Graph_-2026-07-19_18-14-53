## 1. Правки кода

Файлы фазы: см. п. 6. Всё, чего нет в списке, не трогать.

### 1.1. Include `Assets/Shaders/GPU/Includes/ParticleDirection.hlsl` (+ `.meta`)

Include-guard, без URP и без `Core.hlsl`. Одна функция:

```hlsl
float DirectionToValue(float3 velocity, float3 axis)
{
    float lengthSq = dot(velocity, velocity);
    if (lengthSq < 1e-12)
    {
        return 0.5;
    }
    return dot(velocity * rsqrt(lengthSq), axis) * 0.5 + 0.5;
}
```

`axis` ожидается нормированным (нормирует биндер).

### 1.2. `ParticleBillboard.shader`

- Добавить `StructuredBuffer<float3> _Velocities;`, `float _UseDirection;`, `float3 _DirAxis;` (в `CBUFFER`/как остальные свойства, по стилю файла), подключить `ParticleDirection.hlsl`.
- В `vert`: если `_UseDirection > 0.5`, то `value = DirectionToValue(_Velocities[instanceID], _DirAxis)`; иначе прежнее чтение `_Values` при `_UseLut > 0.5`. **Чтение буфера только внутри `if`** (заглушки длиной 1, как для `_Values` и `_TeamIds`).
- Шаг буфера `velocity` должен быть 12 байт: шейдер объявляет `StructuredBuffer<float3>`. В коде `GetStride(Float3)` уже `sizeof(float) * 3`, compute-пассы объявляют `float3`. Это проверить по `GraphicsBuffer.stride` фактически созданного буфера и записать в сдаче. Если шаг 16, остановиться: привязка сдвинет элементы и цвета будут неверны на всех эффектах.
- В режиме `Direction` значения `_UseLut = 1` и `_Scale = 1` выставляет биндер; шейдер ничего не знает про режим кроме `_UseDirection`.
- `ParticlePalette.hlsl` и фрагмент **не менять**. Остальное в шейдере не менять.

### 1.3. `PrimitiveParticleBinder.cs`

- Новый публичный конструктор с двумя дополнительными параметрами `ParticleColorSource colorSource, Vector3 colorAxis` (последние два параметра). Существующие конструкторы **оставить** и сделать так, чтобы они вызывали новый с `colorSource = Value`, `colorAxis = (0, 0, 1)`. Все существующие тесты строят биндер этими конструкторами и обязаны остаться зелёными без правок.
- `Initialize`:
  - `UsesDirectionColor = colorSource == Direction && particles.TryGet(Velocity, out velocityBuffer)`;
  - ось нормируется, нулевая ось заменяется на `(0, 0, 1)`;
  - если `UsesDirectionColor`, LUT нужна всегда (команды: строка за командой как в A1–A3, одиночный режим: LUT из `gradient ?? DefaultFireGradient()` как для `value`). Заглушки для `_Values` создавать, если атрибута `value` нет;
  - если `UsesDirectionColor` ложно, поведение **ровно прежнее**. Новое ничего не логирует.
- `Execute`: при `UsesDirectionColor` выставить `_Velocities`, `_UseDirection = 1`, `_DirAxis`, `_UseLut = 1`, `_Scale = 1`. При ложном: `_UseDirection = 0` и в `_Velocities` положить заглушку (не оставлять невыставленным).
- Публичные `internal` свойства для тестов: `UsesDirectionColor`, нормированная ось.
- A3 (перепекание LUT команд) **не затрагивается**, проверить, что оно работает и в режиме `Direction` (LUT команд общий).
- `Dispose`: освободить заглушку скорости, если создавали.

### 1.4. `EffectAsset.cs` и перечисление

- Новый `enum ParticleColorSource { Value = 0, Direction = 1 }` (в отдельном файле рядом с `ParticleRenderMode` или в том же, по стилю проекта).
- Поля: `[SerializeField] private ParticleColorSource particleColorSource = ParticleColorSource.Direction;` и `[SerializeField] private Vector3 particleColorAxis = new Vector3(0f, 0f, 1f);`, публичные только для чтения свойства.
- Другие поля и поведение эффекта **не менять**.

### 1.5. `SimulationWorld.cs`

Только в `SetupBinders`: передать в конструктор биндера `effect.ParticleColorSource` и `effect.ParticleColorAxis`. Больше ничего.

### 1.6. Пресет двух стай (`M3DDemoTools.cs`, `Boids_hash_2teams.asset`)

- В создателе заменить `FireCyclicGradient()` и `IceGradient()` (и общий `CyclicTeamGradient`) на двухключевые градиенты, режим Blend, альфа 1, ключи в `t = 0` и `t = 1`:

## 2. Тесты

Существующие файлы **не править**, кроме `BoidsHashTwoTeamsPresetTests.cs` (тест самого пресета). Проверки «ассет/шейдер найден» через `Assert`.

1. **`ParticleDirectionTests.cs`** + тестовый compute `ParticleDirectionAddressing.compute` (+ meta) с тем же include, как в A1. Кейсы за один диспатч (ось `(0,0,1)`):
   - скорость `(0,0,1)` даёт 1; `(0,0,-1)` даёт 0; `(1,0,0)` и `(-1,0,0)` дают 0,5; `(0,1,0)` даёт 0,5; нулевая даёт 0,5;
   - `(0,0,5)` даёт то же, что `(0,0,1)` (модуль не влияет);
   - диагональ `(1,0,1)` даёт `0,5 + 0,5/√2` в допуске `1e-5`;
   - ось `(0,1,0)`: скорость `(0,1,0)` даёт 1.
2. **`PrimitiveParticleBinderDirectionTests.cs`:**
   - режим `Direction` с атрибутом `velocity`: `UsesDirectionColor`, `_Velocities`, `_UseDirection = 1`, `_UseLut = 1`, `_Scale = 1` (читать через `MaterialPropertyBlock` или рефлексией, как в существующих тестах);
   - режим `Direction` без `velocity`: `UsesDirectionColor == false`, поведение как `Value` (с `value` и без);
   - прежние конструкторы остаются в `Value`;
   - нормировка оси и подстановка при нулевой оси;
   - режим `Direction` с командами: LUT команд собирается, A3-перепекание работает (смена градиента команды в Editor перепекает LUT);
   - режим `Direction` без команд, без `value`: LUT из `gradient`, плоский цвет не используется.
3. **`PrimitiveParticleBinderDirectionStageTests.cs`** (новый файл; файл стенда A2 **не править**). Рендер реального билборда в линейный RT 256×256, камера как в A2. Нужен собственный рендер-стенд в этом файле (дублирование допустимо, записать в Techdebt). Случаи: два или три квада, команды 0 и 1, скорости вверх, вниз и вбок; центр квада совпадает с цветом из compute-хелпера (A1) при `value = DirectionToValue(...)` в допуске `2/255`; углы совпадают с центром в допуске `1/255`; фон непрозрачный чёрный; цвета палитры ярко ненулевые.
   - Если детерминированный кадр получить не удаётся, остановиться и описать, допуски не расширять.
4. **`BoidsHashTwoTeamsPresetTests.cs`:** заменить тест `TeamGradients_AreCyclicAndReadable` (и `AssertCyclicKeys`) на проверки двухключевых палитр:
   - ключи в `t = 0` и `t = 1` равны указанным (допуск `ChannelTolerance`), число ключей равно 2, режим Blend;
   - для каждой команды 256 отсчётов: HSV `S ≥ 0,5` и `V ≥ 0,4`; расстояние в линейных RGB до фона `(0.136, 0.120, 0.105)` не меньше `0,25` (константа и источник как в A4);
   - расстояние между цветами двух команд при одинаковом `t` не меньше `0,5` на всех 256 отсчётах;
   - цвета в середине (`t = 0,5`) обеих команд различаются не меньше чем на `0,5`.
   Если какое-то условие не выполняется, **порог не ослаблять**, остановиться и описать (я проверил расчётом, что они выполняются).
5. Обновить проверки имён команд и остальные ассерты, которые ссылались на Fire/Ice, в этом же файле.
6. Прогнать весь EditMode. Тесты, которые могут покраснеть из-за смены значения по умолчанию `Direction` (всё, что строит `SimulationWorld` из `EffectAsset` и проверяет состояние биндера или рисунок), **не править**, остановиться и описать, какие и почему.
