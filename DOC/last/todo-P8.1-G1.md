## 2. Этап 2. Безопасные правки

1. **Обёртка индекса без `%`.** В `FieldCic.hlsl` (`WrapCell`) и везде, где в кернелах поля и давления индекс текселя оборачивается целочисленным `%` по вычисляемому разрешению, заменить на условную обёртку: `c += (c < 0) ? r : 0; c -= (c >= r) ? r : 0;` (достаточно одного исправления, пока `−r ≤ c < 2r`). Валидатор: разрешение поля не меньше `2·⌈R/t⌉ + 2` по каждой оси, мелкой сетки не меньше 3 (как сейчас); тест на отклонение. **Результаты всех существующих тестов А, Б, Б3, Б4 остаются в тех же допусках без правок.** Отдельный тест: сетка 150 и углы мира (случай, из-за которого вводили целочисленный модуль в Б3) проходят.
2. **Вычитание собственного вклада в давлении.** Алгебраически собственный градиент равен нулю (парные слагаемые `w00·w10 − w10·w00` и `w01·w11 − w11·w01` сокращаются): убрать `SelfGradient` и вычитание `g − S` в `FieldDensityPressure.compute`. Тесты: одиночная частица `|F| ≤ 1e-5` (20 положений, `Jitter` выключен и включён) и все остальные тесты давления без правок допусков, независимый эталон остаётся прежним (с вычитанием). Если хоть один тест не проходит в прежнем допуске, остановиться и сдать числа, ничего не подгонять.
Коммит. Краткий отчёт.

## 3. Этап 3. Диагностика

1. **Подстадии `press`.** Токены `pclear`, `pscatter`, `pgrad`, `pforce` в конец `FieldRepeatStage` (без перенумерации), ветки `TryParse`/`Name`, подвеска в `FPSDisplay`, допуск в `Tools/s10/run-series.ps1` (только список допустимых значений и текст ошибки). В `FieldDensityPressurePass` при выбранной подстадии повторяется **только** соответствующий кернел: `pclear` очистка (в скрэтч-плотность), `pscatter` сбор (в скрэтч-плотность), `pgrad` градиент из живой плотности в скрэтч-градиент, `pforce` чтение и сила (из живого градиента в скрэтч-скорость, обнуление скрэтч-скорости один раз на `Execute`); первый проход всегда настоящий; остальные стадии повторов не вызывают. `all` и `press` не менять. Тесты: разбор; для каждой подстадии число повторных диспатчей нужного кернела равно `rep − 1`, остальных нулю (счётчик в пассе, доступный тестам); защита В0 (стадия без нужного пасса даёт предупреждение) распространяется на новые токены.
2. **`-Psize`.** Параметр харнесса `-Psize <float>` → `-m3d_psize <float>` (в конец строки, как `-FieldStage`), разбор в `PerfArgs`, применение в `FPSDisplay` к размеру частицы рендера (найти, где хранится `particleSize` сцены; применять на старте, до прогрева), поле `psize=` в логах; без параметра ничего не передаётся и поведение прежнее. Если размер нельзя менять в рантайме без больших правок, остановиться и написать (запасной вариант: сцены-копии с `particleSize` 0,25, что я бы не хотел).
3. **Журнал возможностей GPU.** При запуске приложения (Android, Development Build) одна строка журнала `M3D_GPUCAPS` с именем и версией устройства и API и, для форматов `RGBA16F`, `RGBA32F`, `RG16F` (`R16G16_SFloat`), `RG32F`, флагами `SystemInfo.IsFormatSupported` по `FormatUsage.Sample`, `Linear`, `Render`, `Blend`, `LoadStore`. Одна строка на формат. Парсить харнессу не нужно, строку достаёт `adb logcat -d` после любого прогона и записывается в отчёт.
Коммит. Краткий отчёт.

## 4. Этап 4. Код экспериментов

1. **Микробенчмарк чтения силы (M1).** В `FieldNeighborForcePass` добавить сериализуемое свойство `RepeatReadPattern` (по умолчанию `Normal`) и `RepeatSpan` (число текселей). Образец чтения влияет **только на повторные проходы 2…N стадии `force`** (в скрэтч-скорость), живой проход и поведение не меняются. Образцы: `Normal` (как сейчас); `OneTexel` (все частицы читают углы текселя 0); `LinearById` (индекс текселя `id mod cells`, четыре угла как у обычного чтения от этого индекса, то есть идеальная когерентность); `Span` (индекс `hash(id) mod RepeatSpan`, то есть чтения из первых `RepeatSpan` текселей в случайном порядке). Формулы ядра не менять (только источник индексов и весов); значения скрэтча не используются. Тесты: на `Normal` результат повторов идентичен прежнему; значения живого прохода не зависят от `RepeatReadPattern`.
2. **Порядок обработки по сортировке (A/B).** В `FieldNeighborForcePass` и `FieldDensityPressurePass` свойство `SortedOrder` (по умолчанию `false`): при `true` поток `k` обрабатывает частицу `SortedIndex[k]` из **последней сборки хэша** (`BuildSpatialHashPass` ранее в цепочке; использовать уже существующий буфер отсортированных индексов хэш-набора), результат пишется в `velocity[частицаIndex]` (в давлении то же для кернела сбора и силы). Порядок может быть устаревшим на `K − 1` кадров, это допустимо. Валидатор: `SortedOrder` требует включённого `BuildSpatialHashPass` раньше по цепочке; раскладка хэша должна накрывать мир поля. Тесты: при `SortedOrder = true` результат равен результату `false` (то же поле, те же силы) с точностью до порядка накопления (допуск `1e-5` на частицу); хэш с `RefreshInterval` 3 не ломает тест.
Коммит. Краткий отчёт.
