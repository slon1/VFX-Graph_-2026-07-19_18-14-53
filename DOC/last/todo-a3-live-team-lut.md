## 1. Правки `PrimitiveParticleBinder.cs`

Всё остальное в файле, `ParticleBillboard.shader`, `ParticlePalette.hlsl` и `TeamProfile.cs` не менять.

1. **Ссылка на `teams`.** Сейчас `teams = null;` стоит безусловно сразу после запекания. Заменить:
   - если `UsesTeamPalette`, в Editor ссылку **сохранить**; в плеере (`#if !UNITY_EDITOR`) обнулить;
   - если `!UsesTeamPalette`, обнулить, как раньше;
   - `Dispose` обнуляет `teams` всегда.
2. **Один метод выбора градиента строки.** Сейчас логика `row ?? gradient ?? DefaultFireGradient()` стоит в цикле `Initialize`. Вынести в приватный метод, который берёт `TeamProfile` и запасной градиент. `Initialize` и проверка используют один метод. Запасной градиент (`gradient ?? DefaultFireGradient()`) создаётся один раз при инициализации команд и хранится в поле: `DefaultFireGradient()` создаёт новый объект при каждом вызове, в проверке этого быть не должно.
3. **`BuildLutPixels` без выделения.** Добавить перегрузку `internal static void BuildLutPixels(Gradient gradient, int width, Color[] destination, int offset)`. Существующий `Color[] BuildLutPixels(Gradient, int)` оставить и сделать обёрткой над новой (поведение и значения идентичны; его используют тесты A1 и A2).
4. **Проверка и перепекание, только `#if UNITY_EDITOR`.**
   - Поля: буфер последней загрузки (`Color[]`, `LutWidth * teamCount`), буфер для пересчёта того же размера, счётчик вызовов, один флаг «предупреждение о смене числа команд уже выдано»; `internal const int LiveLutCheckInterval = 8`; `internal int LutCheckCount`, `internal int LutRefreshCount`.
   - В `Initialize` после запекания заполнить буфер последней загрузки теми же значениями, что ушли в текстуру (через новую перегрузку).
   - В начале `Execute` (после проверки `material == null`): если `UsesTeamPalette` и `teams != null`, увеличить счётчик вызовов; каждый восьмой вызов:
     - `LutCheckCount++`;
     - для каждой строки `row < teamCount`: `TeamProfile profile = row < teams.Count ? teams[row] : null`, градиент через общий метод, пересчёт в буфер пересчёта;
     - сравнить буферы **точно** (поля `r`, `g`, `b`, `a`, без допуска);
     - если отличаются: скопировать буфер пересчёта в буфер последней загрузки, `teamLut.SetPixels(буфер последней загрузки)`, `teamLut.Apply(false, false)`, `LutRefreshCount++`. Новый `Texture2D` **не создавать**, `props.SetTexture` не меняется (тот же объект).
   - Если `min(teams.Count, MaxTeams) != teamCount`, один раз `Debug.LogWarning` с понятным текстом («число команд изменилось после Initialize, нужен Rebuild»). Строки не менять, исключений быть не должно.
5. Комментарий в коде на русском или английском в стиле файла: одна-две строки про то, что перепекание только Editor и почему.

## 2. Тесты

Новый файл `Assets/Tests/Editor/PrimitiveParticleBinderTeamPaletteLiveTests.cs` (+ `.meta`). Существующие тестовые файлы **не править**. Проверки «ассет/шейдер найден» через `Assert`, не `Assume`.

Сначала написать тесты, **один раз показать красный прогон** на текущем биндере (счётчики не существуют, поэтому до компиляции потребуются заглушки или временная ветка: если красный прогон невозможен без правки кода, записать это и продолжать), затем реализовать и получить зелёный.

Случаи (контекст `SimContext` и построение биндера как в `PrimitiveParticleBinderTeamPaletteTests`):

1. **Смена градиента команды 1 на месте.** `profile.Color.SetKeys(...)` на том же экземпляре. После `LiveLutCheckInterval` вызовов `Execute`: пиксели строки 1 текстуры равны `BuildLutPixels(новый градиент)` в допуске `1/255` (квантование RGBA32), строка 0 не изменилась, `LutRefreshCount == 1`.
2. **Подмена градиента** (`profile.Color = new Gradient...`). Обнаруживается так же.
3. **Без изменений.** После `3 × LiveLutCheckInterval` вызовов: `LutCheckCount == 3`, `LutRefreshCount == 0`.
4. **Текстура не плодится.** Число живых `Texture2D` с именем `M3D_ParticleBillboard_TeamLUT` до и после перепекания одинаково; объект `teamLut` (рефлексия) тот же экземпляр.
5. **Команда без градиента.** `Color == null` берёт запасной градиент; позднее присвоение собственного градиента обнаруживается.
6. **Список короче.** `RemoveAt` у `List<TeamProfile>`: исключений нет, недостающая строка получает запасной градиент (проверить пиксели), предупреждение выдано (`LogAssert.Expect`).
7. **Список длиннее.** `Add`: исключений нет, текстура прежнего размера, строки не менялись, предупреждение выдано.
8. **`Dispose`.** Поле `teams` (рефлексия) после `Dispose` равно null; поле `teamLut` null (как в существующих тестах).
9. **Без команд.** Биндер без палитры: `teams` (рефлексия) null после `Initialize`, `LutCheckCount == 0` после `Execute` ×16.
10. **Сквозной рендер (необязательно).** Если рендер-стенд из `PrimitiveParticleBinderTeamPaletteStageTests.cs` можно использовать **без правки того файла**, добавить один случай: смена градиента, перерисовка, центр квада совпадает с новым цветом (допуск `2/255`). Если нельзя, пропустить и записать причину. Файл A2 не править.

Дополнительно, не в зелёный набор: однократно измерить время проверки на 8 командах (Stopwatch вокруг `Execute` до и после, разница на проверке; одно число в микросекундах) и убедиться, что проверка без изменений не выделяет память (`GC.GetAllocatedBytesForCurrentThread` до и после пачки проверок, исключая первый вызов). Числа в ADR, в тест не входят.
