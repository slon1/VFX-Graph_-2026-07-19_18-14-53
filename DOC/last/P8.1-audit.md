# P8.1-0 — аудит кода

**Дата:** 2026-11-03. **Ветка:** `feature/p8-field-neighbors`, голова на момент аудита после коммита этапа 1. Решений нет: ниже факты и варианты.

## 1. Хэш

`origin` считает `SpatialHashSet.ComputeLayout`: угол сетки это `center.xz − extents.xz`, размер стороны `2·extents`, ячейка `size / res`.

```116:120:Assets/Scripts/Core/SpatialHashSet.cs
        return new SpatialHashLayout(
            new Vector2(center.x - extents.x, center.z - extents.z),
            new Vector2((float)sizeX, (float)sizeZ),
            new Vector2((float)(sizeX / resX), (float)(sizeZ / resZ)),
            new Vector2Int(resX, resZ));
```

`HashCellCoord` берёт `floor((xz − HashOrigin) / HashCellSize)` и при `HashWrap != 0` заворачивает координату в `[0, res)`.

```12:24:Assets/Shaders/GPU/Includes/SpatialHash.hlsl
int2 HashCellCoord(float2 xz)
{
    int2 c = (int2)floor((xz - HashOrigin) / HashCellSize);
    if (HashWrap != 0)
    {
        c = ((c % HashRes) + HashRes) % HashRes;
    }
    else
    {
        c = clamp(c, int2(0, 0), HashRes - 1);
    }
```

Индекс ячейки линейный: `c.y * HashRes.x + c.x` (`HashCellIndex`, `SpatialHash.hlsl:39-43`).

При `center = 0`, `extents = (112, 0, 112)`, `minCellSize = 1`: `size = 224`, `AxisResolution` даёт `floor(224 / 1 · (1 + 1e-5)) = 224` по каждой оси, ячейка `224 / 224 = 1`. Клеток `224² = 50 176`. Ячейка `c` покрывает `[origin + c, origin + c + 1)`. Если центр текселя `i` стоит в `origin + i·t` при `t = 1`, четыре угла этой ячейки совпадают с центрами текселей `c`, `c+(1,0)`, `c+(0,1)`, `c+(1,1)`.

Шов `walk` 1. Обход 3×3 начинается с `start = i % 9`. Сосед за краем получает сдвиг образа `sx, sy ∈ {−1, 0, 1}`, индекс заворачивается на `HashRes`, и диапазон `CellStarts` сливается со следующим только если `nextStart == rangeEnd` и `sx, sy` те же.

```348:352:Assets/Shaders/GPU/Passes/BoidsPasses.compute
        uint nextStart = CellStarts[cellIndex];
        if (open && nextStart == rangeEnd && sx == rangeSx && sy == rangeSy)
        {
            rangeEnd += slotCount;
            continue;
        }
```

Gather на том же линейном порядке читает два непрерывных отрезка 2×2 (две клетки одной строки). На шве `x = res − 1` соседом по X становится `x = 0`: индексы не соседние, `sx` различается, отрезок разрывается, и к позициям нужен тот же сдвиг `sx·HashSize`, что у обхода.

## 2. Предел

`MaxCells = 256 · 256 = 65 536`. Проверка произведения — строгое «больше».

```123:129:Assets/Scripts/Core/SpatialHashSet.cs
    public static void ValidateLayout(SpatialHashLayout layout, bool wrap)
    {
        long cells = (long)layout.Resolution.x * layout.Resolution.y;
        if (cells > MaxCells)
        {
            throw new InvalidOperationException(
                $"Spatial hash {layout.Resolution.x}x{layout.Resolution.y} = {cells} cells exceeds {MaxCells}.");
```

`AxisResolution` обрезает сырое значение до `MaxCells + 1` (`SpatialHashSet.cs:167-178`). После обрезки произведение всё равно попадает в `ValidateLayout` и при `65 537` по оси бросает исключение: сетка молча не уменьшается до допустимой.

`224² = 50 176` проходит. `256² = 65 536` тоже проходит, потому что сравнение строгое. Квадратный случай `t = 1`: `extents = 128` (мир 256 м), `minCellSize = 1`, `floor(256 · 1.00001) = 256`, ячейка `256 / 256 = 1`. Тот же `res = 256` получается при любой паре, где `floor(size / minCellSize · 1.00001) = 256` по обеим осям, например мир 512 м и `minCellSize = 2`.

## 3. Шаг по времени

Пассам уходит `Time.deltaTime * effect.SimulationSpeed`. Ограничения `dt` в `Update` нет.

```78:80:Assets/Scripts/Runtime/SimulationWorld.cs
        float deltaTime = Time.deltaTime * effect.SimulationSpeed;
        simulationTime += deltaTime;
        context.Time = simulationTime;
```

Techdebt 1b описывает clamp как будущую правку, в этом методе его нет. При `simulationSpeed = 1` шаг равен фактическому `Time.deltaTime`: если кадр игрока 1/30 с, шаг 1/30 с. `SimulationWorld` сам частоту не задаёт. `FPSDisplay` и `HashProbeControls` ставят `Application.targetFrameRate = 120`.

## 4. Пропуск кадров

`ShouldDispatch` есть только у `FieldKernelPass`. При `false` `Execute` выходит, не записав dispatch, и `LastExecuteDispatched` остаётся `false`.

```542:548:Assets/Scripts/Runtime/SimPass.cs
    public sealed override void Execute(SimContext context, float deltaTime)
    {
        LastExecuteDispatched = false;

        if (!kernel.IsValid || primaryDescriptor == null || !ShouldDispatch)
        {
            return;
```

`BuildSpatialHashPass` наследник `SimPass`, не `FieldKernelPass`: этого флага у него нет, флаг dispatch он ставит сам (`SpatialHashPasses.cs:116` и `:212`). `ParticleKernelPass` тоже не имеет `ShouldDispatch`.

Номера кадра в `SimContext` нет. Есть накопленное `Time` (`SimContext.cs:48-49`), это сумма шагов, не индекс кадра. `UnityEngine.Time.frameCount` в контекст не кладётся.

Мир после `Execute` меняет ping-pong только если `LastExecuteDispatched`. `RepeatCount` при этом всё равно крутит цикл: пропущенный пасс вызывается `RepeatCount` раз и swap не делает.

```135:142:Assets/Scripts/Runtime/SimulationWorld.cs
                int repeat = pass.RepeatCount;
                for (int r = 0; r < repeat; r++)
                {
                    pass.Execute(context, deltaTime);
                    if (pass.LastExecuteDispatched)
                    {
                        SwapPingPongFields(pass);
                    }
```

Варианты взять номер кадра, без выбора: свой счётчик в пассе, который растёт в каждом `Execute`; читать `Time.frameCount` снаружи `SimContext`; выводить кадр из `SimContext.Time`, зная что шаг не постоянный.

## 5. Валидатор

Вызов из `SimulationWorld.Build`: `SpatialHashValidator.Validate(effect.Passes, effect)` (`SimulationWorld.cs:226`). Исключение из валидатора роняет `Build` и выключает компонент (`SimulationWorld.cs:238-243`).

`RequireWithinCell` вызывается, когда список команд непуст и в цепочке есть `BuildSpatialHashPass`. Наличия `BoidNeighborForcePass` этот цикл не проверяет.

```217:228:Assets/Scripts/Runtime/SpatialHashValidator.cs
        if (teams.Count > 0 && builder != null)
        {
            SpatialHashLayout layout = SpatialHashSet.ComputeLayout(
                builder.Center, builder.Extents, builder.MinCellSize);
            float limit = Mathf.Min(layout.CellSize.x, layout.CellSize.y) * (1f + SpatialHashSet.GridEpsilon);
            for (int i = 0; i < teams.Count; i++)
            {
                TeamProfile profile = teams[i];
                RequireWithinCell(profile.SeparationRadius, "separationRadius", limit);
                RequireWithinCell(profile.AlignmentRadius, "alignmentRadius", limit);
                RequireWithinCell(profile.CohesionRadius, "cohesionRadius", limit);
```

Бросает, если радиус больше `limit` (`SpatialHashValidator.cs:312-318`). При `R = 3` и ячейке 1 м предел около `1 · (1 + 1e-5)`, исключение есть.

Отдельно, уже в кадре: если `neighborForceEnabled`, мир пишет предупреждение `TeamRadiusPlayCheck`, не исключение (`SimulationWorld.cs:107-114`). Флаг ставится только при включённом `BoidNeighborForcePass` (`SimulationWorld.cs:292-294`).

Варианты условного отключения, без выбора:

1. Обернуть цикл `RequireWithinCell` проверкой включённого `BoidNeighborForcePass`. Тот же `Validate` уже обходит список пассов для classic steer и `AlignFromVelocity`.
2. Вынести проверку радиуса в отдельный вызов и звать его только из цепочек с `BoidNeighborForcePass`.
3. Поле на `BuildSpatialHashPass`, которое полевая цепочка выставляет, а проверка радиуса читает.

Предупреждение `TeamRadiusPlayCheck` само молчит, пока в цепочке нет включённой силы соседей.

## 6. Хранение поля

`FieldDescriptor.GetChannelCount` знает 1, 2 и 4 канала. Шесть каналов в один дескриптор не входят.

```93:106:Assets/Scripts/Core/FieldDescriptor.cs
    public static int GetChannelCount(GraphicsFormat graphicsFormat)
    {
        switch (graphicsFormat)
        {
            case GraphicsFormat.R16_SFloat:
            case GraphicsFormat.R32_SFloat:
            case GraphicsFormat.R8_UNorm:
                return 1;
            case GraphicsFormat.R16G16_SFloat:
            case GraphicsFormat.R32G32_SFloat:
                return 2;
            case GraphicsFormat.R16G16B16A16_SFloat:
            case GraphicsFormat.R32G32B32A32_SFloat:
                return 4;
```

`FieldSet` создаёт пару `RenderTexture`, `enableRandomWrite`, `filterMode = Bilinear`, `wrapMode = Clamp` (`FieldSet.cs:67-79`). Формат без `LoadStore` на устройстве — исключение (`FieldSet.cs:25-28`). Ping-pong делает мир после dispatch. Слоты одного поля — `FieldRead` / `FieldWrite` (ADR-003). Два поля в одном кернеле — роли A/B (ADR-008). Третьего слота нет, поэтому три поля по RG в один кернел текущий биндер не кладёт. Два поля, 4 и 2 канала, в роли A/B укладываются.

`sampler_linear_repeat` объявлен в `AdvectScalar` и используется при `AdvectWrap != 0` (`FieldPasses.compute:220`, `:243-246`). Адрес задаёт сэмплер шейдера; `wrapMode` текстуры при создании остаётся Clamp. Тот же приём есть в `PhysarumPasses.compute:15`.

`SpatialHashSet` хранит `GraphicsBuffer` без сэмплера и без проверки формата текстуры (`SpatialHashSet.cs:46-55`). Билинейная выборка из такого буфера считается в шейдере вручную.

ADR-035 про другое: без атрибута `value` Vulkan выбрасывает кадр квадов из-за пустых слотов `_Values` и `_LutTex`. Биндер подставляет буфер из одного float и текстуру 1×1 (`ADR-035`, раздел «Решение»). К формату поля это не относится. Непривязанная текстура compute на Vulkan — тот же класс ошибки «missing bindings», который ADR зафиксировал на отрисовке.

Документация Unity 6, `GraphicsFormatUsage.Linear`: флаг значит выборку с линейным фильтром. Страница не перечисляет форматы Mali-G76. Поддержка спрашивается через `SystemInfo.IsFormatSupported(format, GraphicsFormatUsage.Linear)`. URP в `PostProcessPass` берёт `R16G16B16A16_SFloat` с `FilterMode.Bilinear` и проверяет `R16_SFloat` на `Linear | Render`, прежде чем выбрать его. На устройстве это не проверялось.

## 10. Отклонения от ADR-058 и ADR-059

1. ADR-058 §2.1.4 называет `ShouldDispatch` для пассов хэша, сбора и свёртки. У `BuildSpatialHashPass` этого свойства нет: оно объявлено на `FieldKernelPass` (`SimPass.cs:466`). Пропуск кадра у хэша — ранний выход внутри его собственного `Execute` с `LastExecuteDispatched = false`.
2. Номера кадра в `SimContext` нет (раздел 4). ADR рассчитывает на кадр `s % K`.
3. Шаг пассов — `Time.deltaTime * SimulationSpeed`, без деления на целевой FPS и без clamp (раздел 3). ADR-059 §2.3 и ТЗ говорят про шаг `simulationSpeed / FPS`.
4. `RequireWithinCell` срабатывает на любой цепочке с командами и билдером хэша, в том числе без `BoidNeighborForcePass` (раздел 5). ADR-058 §2.4 описывает исключение при `R = 3` и ячейке 1 м и оставляет условное отключение на потом; текущий предикат шире, чем «только цепочки с силой соседей».
5. `TeamParams` на этой ветке 64 байта и содержит `Classic`. Формула `m(a, g)` из ADR-058 §2.1 с `Radii.w` совпадает (раздел 7). ADR размер слота не называет.
6. `Boids_hash400k_2teams` хранит выключенный `HashCountsToField` и поле `hashCount`. Включённый порядок пассов списку P400c соответствует (раздел 9).
