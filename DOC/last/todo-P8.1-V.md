# ТЗ: P8.1-В, замер на S10 (P400c: кап 48, кап 192, поле, давление)

**Исполнитель:** Composer (или Grok). **Ревью:** Claude и владелец.
**Куда положить:** `DOC/last/todo-P8.1-V.md`.
**Основа:** [ADR-063](../ADR/ADR-063-P8-1-B4-Density-Pressure.md) §5 (оценка цены, ловушки), [ADR-062](../ADR/ADR-062-P8-1-B-Field-Force-And-Behavior-Probe.md) §2.9, план `plan-P8-field-neighbors.md` (строка P8.1-В и гейты), ТЗ В0 (`todo-P8.1-V0.md`) и его отчёт, `DOC/MEASURE/README.md`, `.cursor/skills/s10-measure/SKILL.md`, отчёт А `P8.1-report.md` (раздел «А: микробенч», метод наклона по `rep`).
**Что делает это ТЗ.** Замер на Galaxy S10 (Mali-G76, 720 × 1520) на сценах P400c (400 000 частиц, мир 224 м): кадр режимов B и A для базы (кап 48, кап 192) и для поля без давления и с давлением (K = 1 и K = 3), цена каждой стадии (`collect`, `conv`, `grad`, `force`, `press`, `all`) по наклону между двумя `rep`. **Код не менять.** Вердикт GO или NO-GO не писать: его ставит ревью по плану.

## 0. Условия

1. **Сборка.** Владелец собрал приложение из `6d776be` (вершина ветки `feature/p8-field-neighbors`, V0) и установил на S10 (serial по умолчанию `RF8N31SLV7N`, при ином `-Serial`). Проверить `git rev-parse HEAD` (ожидается `6d776be` или потомок только с документами) и `git status --short`: допустимы `M Packages/manifest.json` и коммиты только с файлами в `DOC/`; код и сцены на момент замера совпадают с `6d776be` (проверить `git diff 6d776be HEAD --stat` — в выводе только `DOC/`). `Packages/manifest.json` не коммитить. Все серии запускать с `-ExpectBuild 6d776be`; логи с другим `build` невалидны.
2. **Телефон запускать только после слова владельца в чате** («телефон подключён и заряжен» или «запускай»), заряд не меньше 50%. Если заряд ниже 40% посреди серии, остановиться и написать. Предварительно: `powershell -NoProfile -ExecutionPolicy Bypass -File Tools/s10/preflight.ps1`; `low_power` = 0, иначе замер не начинать; короткая сторона 720.
3. **Код, шейдеры, сцены, пресеты, `Tools/s10` не менять.** Если харнессу нужна правка, остановиться и написать. Команды только из корня репозитория, скриптами `Tools/s10`. Streamline, `.apc`, APK, `Tools/s10/out/` не коммитить. Новый парсер CSV не писать.
4. **Валидность.** Точка принимается, если в логе `devbuild=1`, `applied=1`, `powersave=0`, нет `M3D_PERF_WARN`, `build` равен `6d776be`, строка `args` совпадает с ожидаемой харнессом. Невалидную точку повторить (не больше двух раз), причины перечислить в отчёте. `dirty=1` допустим (записать `dirtyhash`).
5. Параметры точки: прогрев 60 с, окно 25 с, пауза 60 с (значения харнесса по умолчанию), не менять. Использовать `-Resume` при обрыве.
6. Пересчёт в циклы на частицу: `мс × 1,75` (700 МГц, 400 000 частиц, формула плана); частота GPU не снималась, допущение записать.

## 1. Сцены и ассеты (все в Build Settings, подтверждено В0)

| код | сцена | что внутри |
| --- | --- | --- |
| BASE | `Boids_Hash_P400c` | хэш и обход, кап 48 (по умолчанию `-m3d_maxn 48`), база |
| BASE192 | та же сцена с `-MaxN 192` | кап 192 |
| FIELD | `Boids_Hash_P400c_Field` | поле 1 м Scatter, K = 3, сила, **без давления** |
| PK3 | `Boids_Hash_P400c_Field_Press_K3` | поле, сила, давление (droplet: вес 0,8, `g0` 25), K = 3 |
| PK1 | `Boids_Hash_P400c_Field_Press_K1` | то же, K = 1 |
| SCAT | `Boids_Hash_P400c_FieldScatter` | только сбор, свёртка, градиент (проверка согласованности с А) |

## 2. Фаза 1: кадр (обязательно для решения)

Для каждой сцены серия `BABAB` (три точки B, две точки A):

```
powershell -NoProfile -ExecutionPolicy Bypass -File Tools/s10/run-series.ps1 -Series BABAB -Scene <сцена> -ExpectBuild 6d776be -Tag v-<код>-
```

Порядок сцен: BASE, BASE192 (`-MaxN 192`), PK3, PK1, FIELD, SCAT. Гейт сдачи требует BASE, BASE192, PK1, PK3; FIELD и SCAT при нехватке батареи или времени можно сдвинуть на другую сессию или пропустить с записью в отчёт. Между сценами пауза 60 с, по возможности охлаждать устройство дольше, если `thermal` в логе растёт. Результат: `DOC/MEASURE/6d776be-<dirtyhash>/<метка>/` (харнесс создаёт сам), `summary.md` через `summarize.ps1`.

**Ограничение метода (урок А):** кадр режима B на vsync (16,71 мс) не показывает цену ниже запаса. Если медиана B меньше 17 мс, записать «не выше vsync» и оценку кадра при `rep 1` брать из фазы 3 (`all`), не из этих точек.

## 3. Фаза 2: цена стадий на PK1 (метод наклона)

Только режим B, сцена PK1 (`-Scene Boids_Hash_P400c_Field_Press_K1`), серия `BBB` на точку: `-FieldStage <стадия> -FieldRep <rep>`. Пары `rep` (оба значения выше vsync):

| стадия | rep (нижний / верхний) |
| --- | --- |
| collect | 8 / 16 |
| conv | 16 / 32 |
| grad | 32 / 64 |
| force | 16 / 32 |
| press | 8 / 16 |
| all | 4 / 8 |

**Правило:** медиана нижней точки должна быть не меньше 20 мс. Если нет, поднять оба `rep` вдвое (до 64) и записать фактические; если и тогда ниже 20 мс, записать «ниже разрешения, оценка сверху (20 мс − кадр базы)/rep» и не выдавать наклон. Наклон `(медиана_верх − медиана_низ) / (rep_верх − rep_низ)`, мс на проход. Для `all` наклон равен суме стадий на кадр при K = 1.

Каждая стадия с давлением или силой запускается **только на PK1** (В0: стадия без пасса даёт предупреждение и невалидный прогон, `M3D_PERF_WARN` в логе).

## 4. Фаза 3: сопровождающие расчёты (без запуска)

Отдельный `BBB` / `all` на PK3 **не** запускать: только расчёт из наклонов PK1 и точек фазы 1.

1. Оценка кадра B при `rep 1` на PK1 (не зажатая vsync): `медиана(all, rep 8) − 7 × наклон(all)`.
2. Кадр без поля: `кадр(PK1, rep 1) − (collect + conv + grad + force + press)` (наклоны стадий с PK1).
3. Среднее на кадр при K = 3 (контроль, только расчёт): `(collect + conv + grad)/3 + force + press + (кадр без поля)`. Сравнить с измеренным B(PK3) из фазы 1, если он выше vsync; расхождение больше 15% записать в отчёт, причину не искать.
4. Цена давления при K = 3: измеренная разница B(PK3) − B(FIELD) против наклона `press` с PK1 (на PK3 давление каждый кадр, вклад не делится на K). FIELD — `Boids_Hash_P400c_Field` (поле с силой, без давления), не BASE. Если FIELD сдвинут или пропущен из-за батареи/времени, пункт не выполнять и записать это в отчёт. Сравнение с BASE (кап 48) — отдельно в таблице 4 отчёта.
5. Согласованность с А: сумма наклонов `collect + conv + grad` на PK1 против 9,60 мс из ADR-061 §5 (допуск 15%). Расхождение записать, не искать причину.
6. Контрольный вывод про шум измерения: разброс трёх точек B по каждой серии (мин и макс).
