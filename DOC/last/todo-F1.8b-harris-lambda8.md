### Шаг 1 — сид: развязать частоту и амплитуду

Геометрия как F1.8: `Size = Resolution = 64` (`h = 1`), `dt = 1`, Jacobi×40, оба `.compute`.

**Писать в логе оба имени**, чтобы не путать с 3.6:

| Имя | Значение |
| --- | --- |
| длина волны | **8 текселей** |
| периодов на 64² | **8** (тот же класс, что 3.6 `k=8` / 4.46×; **не** F1.8 с 16 периодами) |
| `κ` | `2π / 8` |

Форма (алгебраическое `D≡0` на стенсиле держится при любом `A`, не только `A=κ`):

```
u = A · ( sin(κ x) cos(κ y),  −cos(κ x) sin(κ y) )
A = 1    // max|u| = A → сдвиг A·dt/h = 1 тексель/шаг при h=dt=1
```

Не оставлять `A = κ`. В F1.8 `A=κ` и `λ=4` давали ~1.57 текселя/шаг **и** дыру k=16 сразу.

`plane` — тот же `PlanePosition`, что сейчас.

Опционально (не блокер закрытия): второй `[TestCase]` с `λ=16` текселей (4 периода на 64²), тот же `A=1`. Если нет времени — только λ=8.

Существующий тест λ=4 (`κ=2π/4`, `A=κ`) **оставить** отдельным методом или `[TestCase]`, не переписывать числа F1.8.

### Шаг 2 — гейты

Как F1.8, плюс один новый **только у порядка B, кадр 1**:

1. `maxAbsInterior(seed) < 1e-3`.
2. Нет NaN/Inf на всех точках.
3. `afterAdvect` кадра 1 обоих порядков `> 1e-3` и `> 10×` сида.
4. **Частота валидна для вывода про порядок:** у B кадр 1 `maxAbsInterior_afterChain < maxAbsInterior_afterAdvect`.  
   Если **не** меньше (проекция снова растит D) — `Assert.Fail` с числами: эта λ снова в дыре Jacobi, **не** интерпретировать A vs B. Не подгонять `A`/`λ` молча.

`afterChain(B) < afterChain(A)/2` **не** ассертить. В отчёт — явно, на скольких кадрах из 8 выполняется, и отношение B/A по кадрам.

Инвариант «проекция уменьшает D» у порядка A мерить **нельзя** на `afterChain` (там уже Advect). Только B: `afterAdvect` → `afterChain`.
