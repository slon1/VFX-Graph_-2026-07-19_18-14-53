## Зачем

В Play стаи на сцене `Boids_Hash_2Teams_Field` за 5–10 с превращаются в тонкие цепочки частиц (линии шириной в одну частицу). Зонд Б этого не поймал, потому что его метрики (`contact`, `enemy`, `flocks`, `pol`, `turn`) на линиях выглядят хорошо. Упрощённая модель numpy воспроизводит схлопывание и связывает его с силой разделения поля. Здесь нужно проверить, **повторяет ли это движок**, и сколько стоит K = 3. Код пасса силы, шейдер, пресеты, формулы и пороги **не менять**: это только измерение.

## 1. Метрики (определения обязательны, они совпадают с моделью)

Считаются на CPU по `Position`, `Heading`, `TeamId`, R = 3, расстояния по минимальному образу мира 90 м; сэмплы t = 2, 5, 10, 15 с (кадр `round(t·FPS)`). Три сводки по всем частицам обеих команд:

1. **`rhoOwn`**: на частицу `(число своих соседей в R, без себя) / (π·R²)`, единицы 1/м². В сводку медиана (`rhoMed`) и 90-й процентиль (`rhoP90`).
2. **«Линейность»** `thin`: для частицы, у которой выборка своих в R (**включая саму частицу**, её смещение нулевое) содержит не меньше 6 точек, то есть не меньше 5 других, берутся смещения выборки относительно этой частицы, `C` её ковариация (выборочная, `ddof = 1`), `thin = sqrt(λ_min / λ_max)` по собственным значениям `C` (при `λ_max ≤ 1e-12` считать 1). Сводка: медиана `thin` (`thinMed`) и доля частиц с `thin < 0,25` среди учтённых (`fracThin`).
3. **Занятые клетки** `cells`: число различных пар `(floor((x + 45)/1), floor((z + 45)/1))` по всем частицам (мир 90 м, клетка 1 м).

Дополнительно две диагностики ориентации:

4. **`axisHead`**: доля частиц, у которых `atan2(h.z, h.x)` по модулю 90° лежит в пределах 5° от нуля (курс вдоль осей мира); случайному распределению отвечает 0,11.
5. **`axisLine`**: среди частиц с `thin < 0,25` доля тех, у которых направление главной оси `C` (собственный вектор `λ_max`) по модулю 90° лежит в пределах 10° от осей мира; случайному распределению отвечает 0,22.

## 2а. Уточнения (2026-11-05, по вопросам исполнителя)

1. **Порог 6** считается по выборке с самой частицей: нужно не меньше 6 точек, то есть не меньше 5 других своих в R. (В README модели слова были неточны, исправлено.)
2. **Сосед в R:** `r² < R²`, как в зонде Б. Модель использовала `r ≤ R`; на непрерывных данных разницы нет, на решётке она есть, поэтому ручные значения ниже посчитаны для `r² < R²`.
3. **Ковариация:** выборочная (`np.cov`, вычитание среднего, `ddof = 1`) по смещениям выборки с самой частицей.
4. **Пустые сводки:** `NaN` в числах нет. Если ни одна частица не вошла в `thin`, `thinMed`, `fracThin` и `axisLine` не определены: в коде `double?` без значения, в CSV пустая ячейка, в `.md` прочерк. Добавить колонку **`nThin`** (сколько частиц вошло в сводку `thin`); при усреднении по seed брать только seed с данными и писать их число (колонка `seedsWithData`).
5. **`λ_min < 0`** от округления зажимать в 0 (`thin` на идеальной цепочке равен 0, без NaN).
6. **Статистики:** медиана при чётном числе значений равна среднему двух центральных; `rhoP90` линейной интерполяцией по рангу `(n − 1)·0,9` (как `np.percentile` и `Percentile` в сравнении силы).
7. **`axisHead`, `axisLine`:** угол до ближайшей оси (0°/90°/180°/270° для курса, 0°/90° для направления линии), пороги включительно, `≤ 5°` и `≤ 10°`. Случайные доли 40/360 ≈ 0,11 и 80/360 ≈ 0,22.
8. **Ручные тесты, конкретные значения** (посчитаны и проверены):
   - диск: 200 точек по спирали Фогеля, `r_k = 2·sqrt((k + 0,5)/200)`, угол `k·π·(3 − √5)`, радиус диска 2 м; ожидается `thinMed ≥ 0,8` (расчёт даёт 0,89, минимум 0,74);
   - цепочка 60 точек, шаг 0,1 м: все частицы учтены, `fracThin = 1`, `thinMed ≈ 0` (допуск 1e-6); `axisLine = 1` при цепочке вдоль x и `0` под 45°;
   - решётка для `rho`: 15 × 15 узлов с шагом 0,5 м (±3,5 м), проверяется **центральный узел**, не медиана по всем: в `r² < 9` попадает 109 точек с самой частицей, `rhoOwn = 108/(9π) = 3,819718634205` (допуск 1e-9);
   - шов тора: `|thinMed − thinMed без шва| ≤ 1e-9`;
   - остальные ручные тесты, как в этапе 1.
9. **Таблица «движок рядом с моделью»:** для t = 5 с (и вторым блоком t = 10 с из README): модель (seed 1, 60 кадров/с, обход и поле K = 1) и движок: seed 1 при 60 кадров/с и среднее по 5 seed, варианты обход без капа, кап 48 (у модели нет, прочерк), поле K = 1, поле K = 3. Метрики `fracThin` и `cells`.
10. **Репозиторий:** четыре неотслеживаемых пути (ADR-062, оба ТЗ Б и Б2, `model-shape-check/`) на этот заход разрешены, как и в Б. Первым коммитом добавить именно их (только документы, без кода). Если в дереве есть что-то ещё, остановиться и спросить. Скрипты модели в каталог могут быть добавлены позже; README на них ссылается, но тесты и отчёт от них не зависят.
11. **Коммиты и имена файлов:** три коммита (документы; метрики и ручные тесты; матрица, отчёт, абзац ADR). Файлы `shape-<хеш>.csv/.md` называть по хешу коммита метрик (кода, которым сняты данные), не по хешу коммита, который их содержит.

## 3. Текст для ADR-062 §2.7 (внести)

> **Дополнение 2026-11-05: метрики формы.** К метрикам зонда добавлены `rhoMed`, `rhoP90` (своя плотность в R, 1/м²), `thinMed`, `fracThin` (доля частиц с `sqrt(λ_min/λ_max) < 0,25` у ковариации смещений своих соседей в R, не меньше 6 соседей), `cells` (занятые клетки 1×1 м) и диагностики `axisHead`, `axisLine`. Эти метрики порогами пока не служат, пороги задаст ревью после замера в движке.
