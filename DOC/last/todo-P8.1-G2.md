## 2. Этап 2. Давление с пониженной частотой

В `FieldDensityPressurePass` два целочисленных свойства (по умолчанию 1, диапазон 1…4, валидатор):

1. **`GridUpdateInterval`.** Мелкая сетка плотности и градиент (`pclear`, `pscatter`, `pgrad`) строятся только на кадрах, где `frameIndex % GridUpdateInterval == 0`. На остальных кадрах очистка, сбор и градиент **не выполняются**, а чтение (`pforce`) использует сохранённый градиент прошлой сборки. Сдвиг начала сетки (`Jitter`) берётся **на кадре сборки** и сохраняется до следующей сборки: чтение должно использовать тот же сдвиг, что сбор. Счётчик кадра растёт на каждом `Execute`, как сейчас.
2. **`ForceInterleave`.** Сила давления пересчитывается для частицы только на кадре, где `(hash(index) + frameIndex) % ForceInterleave == 0` (устойчивый хэш индекса, не непрерывные блоки), и сохраняется в буфере `PressureForce` (`float2` на частицу, выделять только при `ForceInterleave > 1`). На остальных кадрах в `velocity` добавляется сохранённое значение. Для частицы, которая ещё ни разу не считалась (первый кадр), считать сразу.

При значениях 1 и 1 поведение и результаты **побитово прежние** (все тесты Б4, В0, G1 без правок допусков). Стадии диагностики (`press`, `pclear`, `pscatter`, `pgrad`, `pforce`) работают как раньше; повторы подстадий выполняются на кадрах, где подстадия выполняется (на пропущенных кадрах повторов нет), это записать в отчёт.

Тесты (EditMode, GPU): (а) при `GridUpdateInterval 2` сетка собирается ровно на каждом втором кадре (счётчик сборок в пасcе доступен тестам), а на нечётных кадрах сила давления вычисляется по прошлому градиенту; (б) при `ForceInterleave 2` сила каждой частицы пересчитывается каждый второй кадр, группы чередуются, сохранённое значение на пропущенном кадре равно значению прошлого кадра; (в) одиночная частица: `|F| ≤ 1e-5` при (1,1), (2,1), (1,2), (2,2), 20 положений, `Jitter` включён и выключен; (г) плотная толпа (из тестов Б4) при (2,2): силы конечны, `|F| ≤ Weight`, `ΣN` по обоим полям сохраняется; (д) воспроизводимость: два прогона по 30 кадров на одном экземпляре эффекта при (2,2), позиции в 1e-6; (е) валидатор отклоняет значения вне диапазона 1…4. Коммит. Краткий отчёт.

## 3. Этап 3. Сортировка для сбора поля

1. В `FieldNeighborCollectPass` (режим Scatter) свойство `SortedOrder` (по умолчанию `false`): при `true` поток `k` кернела `FieldScatter` обрабатывает частицу `SortedIndices[k]` из последней сборки хэша (механизм как у `pscatter` в G1; границы по `ParticleCount`). Валидатор: `SortedOrder` у сбора требует `BuildSpatialHashPass` раньше по цепочке и совпадающий `RefreshInterval`, как у силы и давления (правило «Scatter рядом с хэшем разрешён только при `SortedOrder`» расширить на сбор). Результат: целочисленные атомики, поэтому **`Accum` после сбора при `SortedOrder = true` побитово равен `false`** (тест на равенство буферов).
2. В `FieldDensityPressurePass` добавить свойство `ScatterSorted` (по умолчанию `false`): сортированный порядок только для кернела `PressureScatter`, чтение (`pforce`) остаётся в обычном порядке (в G1 именно чтение ухудшилось). Прежний `SortedOrder` не менять (сохраняется для существующих сцен G1: при `true` он сортирует и сбор, и чтение); если `ScatterSorted` и `SortedOrder` включены, ведёт себя как `SortedOrder`. Тест: `Density` при `ScatterSorted = true` побитово равна `false`.
Коммит. Краткий отчёт.
