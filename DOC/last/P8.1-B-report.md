## Отклонение от ТЗ §3.3(в)

Владелец (2026-11-05): ошибка в допуске ТЗ, не в кернеле. Формула силы не менялась.

ТЗ просило одну проверку: 5 000 случайных частиц, velocity против `FieldRead` по double-полю `FieldNeighborReference`, допуск `max(2×10⁻⁴, 2×10⁻³·|F|)`. На Scatter этот допуск не держится: максимум 1,52×10⁻³, 23 из 5 000 частиц (0,46%). Кернел при этом совпадает с `FieldRead` по полю, которое цепочка сама записала.

Вместо одной проверки три, мир 64 м, `t = 1`, seed 1, 5 000 частиц, две команды:

| Проверка | Результат | Предел |
| --- | --- | --- |
| velocity против `FieldRead` по `Field`, прочитанному с GPU после свёртки (Scatter) | максимум 1,21×10⁻⁶ | 1×10⁻⁵ абсолютно |
| Gather (хэш, сбор Gather, свёртка, сила) против double-эталона | максимум 3,09×10⁻⁶, за допуском ТЗ 0 / 5 000 | `max(2×10⁻⁴, 2×10⁻³·|F|)` |
| Scatter против double-эталона | максимум 1,52×10⁻³, за допуском ТЗ 23 / 5 000 (0,46%) | максимум не больше 3×10⁻³, доля не больше 1%. Подпись теста: «регрессионный предел по наблюдаемому разбросу фиксированной точки» |

Эта запись относится только к допуску того теста. Сравнение силы с обходом (§2.6) меряет весь путь Scatter: квантование остаётся внутри ошибки, из неё ничего не вычитается.

У капа 48 и 192 пасс пишет в `velocity` только сумму, поэтому колонки `F_sep`, `F_align`, `F_coh` в таблицах пустые. У поля эти компоненты сняты с `Field`, которое цепочка сама записала. Угол и модуль `F` у всех трёх вычислителей берутся из `velocity`. Пассы обхода не менялись.

Полный EditMode после сдачи ещё раз переписал таблицы капа (строки поля совпали). Пример: t = 0, кап 48, медиана угла 22,24, затем 21,77. Файлы возвращены к прогону `91e5602`.
