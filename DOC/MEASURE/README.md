## Протокол замеров (с 2026-10-12)

Энергосбережение выключено (`settings get global low_power` равно 0), телефон на кабеле. Пауза между точками серии 60 с. Скрипт не меняет разрешение, яркость и режим питания. Состояние экрана `Dozing` на старте точку недействительной **не делает** (приложение прогревается из него); `wakefulness` фиксируется как информация ([ADR-046](../ADR/ADR-046-Perf-Target-And-P6-Closure.md)). Перед серией — `Tools/s10/preflight.ps1`. Приложение перезапускается на каждую точку. Окно замера 25 с. В имя файла лога входит короткая сторона `res`: 720, 1080 или 1440. Полное `res` остаётся в логе. В этой базе телефон был горизонтальным: `1520×720`, `2280×1080`, `3040×1440`.

Три вида замера. Быстрый — харнесс на текущем разрешении, серия из пяти точек: сила и рендер, только сила, снова оба, снова только сила, только рендер. Профиль — Streamline, захваты «сила без рендера» и «рендер без силы», метрика для сравнений кода — циклы GPU на кадр. Проверка высоких разрешений редкая: режим экрана ставит владелец, затем идёт тот же быстрый замер. Медиана по повторам. Шум: разница кадра меньше `max(2 × разброс, 0,5 мс)` или меньше 0,03 по доле длинных кадров. Порог шума и критерий приёмки изменения кода: [ADR-046](../ADR/ADR-046-Perf-Target-And-P6-Closure.md) §2.3.

Сборка этой базы `6ac1cad`, `dirty=1`, `dirtyhash=f3017014`. `devbuild=1`, `powersave=0`. Свойство `dirty=1` входит в базу: в APK попали незакоммиченные правки дерева.

Команды из корня репозитория:

```
powershell -NoProfile -ExecutionPolicy Bypass -File Tools/s10/preflight.ps1

```


## Как читать логи

Строка `M3D_PERF` пишет `count`, `maxNeighbors`, `force`, `render`, `debug`, `phase` (`WARMUP`, `MEASURE`, `DONE`), `t`, `frameAvg`, `frameP95`, `frameMax`, `long` (доля длинных кадров), `cpuFrame`, `cpuMain*`, `cpuRender*`, `cpuWait*`, `gpuAvg`, `gpuP95`, `thermal`, `thermalStart`, `thermalMax`, `buckets`, `res`, `hist`. `debug=na` значит, что оверлей `FieldDebugQuads` не найден. Кнопка силы отключает только обход соседей: хэш и steer продолжают работать. Кнопка рендера отключает только отрисовку частиц (`RenderParticles = false`). Окно харнесса `Assets/Scripts/FPSDisplay.cs`: 30 с прогрева и 30 с замера.

`hist` — шесть корзин с границами 15, 18, 25, 36, 55 мс. Примерные кластеры кадров: 16,7 / 33 / 50 / 67+ мс.

`thermal` во всех этих логах равен 0 и не отражает изменения частот.

Средний кадр между 16,7 и 33,3 мс — это доля кадров, пропустивших vsync. Текст объяснения в [ADR-040](../ADR/ADR-040-Boids-Hash-Preset-And-Play-Gate.md), errata 4; здесь он не повторяется.

`gpuAvg` читать только когда есть длинные кадры. Пока кадр стоит на vsync, это поле не стоимость работы (errata 2 того же ADR). Для `gpuAvg` и столбцов `cpu*` в Player Settings нужен `enableFrameTimingStats: 1` (записан в `0bfff13`).

## Правила сравнения

Одно разрешение, одна сцена, режимы по кругу, минимум два повтора. Разница меньше 0,5 мс по `frameAvg` или 3 п. п. по `long` — шум: это удвоенный разброс повторов 0,13–0,25 мс.

Разрешения 1520×720 и 2280×1080 рабочие для прогонов до 2026-10-12. 3040×1440 в тех прогонах для сравнений не использовать. Набор `df9748d/` базой сравнений на 3040×1440 не является. В базе `6ac1cad-f3017014/` разрешение 3040×1440 есть, см. протокол выше.

## Исключения

Прерванный прогон на 2280×1080: в `df9748d/m3d_perf.csv` два `WARMUP t=10.0` подряд. У прерванного прогона строки `DONE` нет.

Пара «рендер выкл» на 3040×1440 нестабильна (30,97 и 21,91 мс при одной конфигурации). В сравнениях эту ячейку не использовать. Строки из CSV не удалять. Причина не выяснена. Подробности в ADR-040, errata 5.

В выдержках, вставленных в чат, первая строка обрезана. В CSV та же строка целая.

## Чего в логах нет

Способ смены разрешения (системная настройка Samsung). В прогонах до E1a нет хэша сборки и имени сцены. Для `d9bba9c/` и `27c7c4c/` сцена — `Boids_Hash.unity`, эффект — `Boids_hash30k.asset`: в репозитории такой ассет есть, в строках лога его нет.

Настройки URP и Quality сборки. Render scale 0,8, HDR включён, MSAA выключен, фильтр апскейла одинаковы в HEAD и в рабочем дереве, поэтому по этим четырём полям 2026-10-06 и 2026-10-10 не расходятся. APK собирали из рабочего дерева, и в git этого нет. На тот момент незакоммичено было три отличия: текущее качество PC → Mobile, LUT цветокоррекции 32 → 48, prefilter point sampling 0 → 1.
