# CPU-модель полевой силы соседей (P8)

**Дата:** 2026-11-02. **Автор:** Claude (по заданию владельца, ветка `feature/reynolds-boids`).
**Назначение:** проверка идей замены обхода соседей полями до написания GPU-кода. План [`plan-P8`](../../plan-P8-field-neighbors.md), решение [`ADR-054`](../../ADR/ADR-054-Field-Neighbor-Force.md).
**Статус:** исследовательский код. В Unity не подключён. Числа это CPU, не GPU.

## 1. Что смоделировано

Те же правила и числа, что в GPU-пресете `Boids_hash_2teams`: две команды по 1500 частиц, диски радиуса 12 на расстоянии ±22, мир 90 м с переносом, `R = 3` у всех трёх правил, веса separation / alignment / cohesion 1,2 / 0,8 / 0,6, множитель чужих 4, `cruise = 6`, `turn = 4`, `dt = 1/60`. Сила: `F = sep/sepN·wS + unit(Σ headings)·wA + unit(mean displacement)·wC`, alignment и cohesion по своей команде, separation по всем (`−d/(r²+0,001)`, чужие ×4). Курс: `lerp(h, unit(F), min(turn·dt, 1))`, нормировка. Совпадает с кернелом `BoidNeighborForce` (ADR-038) и `TeamHeadingSteer`.

Модель выполняет шаги на CPU, числа из неё нельзя читать как цену на GPU.

## 3. Сборка

```
g++ -O2 -std=c++17 -o fm field_model_all.cpp
g++ -O2 -std=c++17 -o split boids_model_split_caps.cpp
```
MSVC: `cl /O2 /std:c++17 /EHsc field_model_all.cpp`. Других зависимостей нет.

## 4. Запуск полевой модели

```
./fm <mode> <G> <seed> <T> [args...]        # T в секундах, печать на t=1, 5 и 15
```
`G` — число дальних текселей по стороне (мир 90 м, `t = 90/G`), для режима 0 не используется (передать 1). Печать в строки вида:
```
t=5 contact=1.9 enemy=0.08 flocks=2,2 pol=0.992 turn=0.0075 turnSd=0.0081 vis=11.6 vis3=490.2 visMax=34 rhoOwn50=… rhoOwn90=… rhoAll50=…
```

| Режим | Что | Аргументы, окружение |
|---|---|---|
| 0 | эталон: точный обход без капа | `./fm 0 1 <seed> <T>` |
| 1 | дальнее поле: сила `−d/r²` векторным ядром, всё на поле | `./fm 1 <G> <seed> <T>` |
| 2 | alignment и cohesion на поле, separation точный без капа | `./fm 2 90 …` |
| 3 | как 1, без исключения собственного вклада | `./fm 3 90 …` |
| 4 | поле + точный обход `r < r0` по мелкой сетке хэша | `./fm 4 90 <seed> <T> <r0>` |
| 5 | поле (векторное) + окно из центроидов (NGP, мелкая сетка) | `./fm 5 90 <seed> <T> <Gn> <k> <ownExact>` |
| 6 | давление по плотности как separation | окружение `P_H P_RHO0 P_GAMMA P_GAIN P_MU P_RS P_EMA P_CLAMP`, `./fm 6 90 <seed> <T>` |
| 7 | потенциал и градиент, точное ядро `ψ`, без ближнего поля | `./fm 7 <G> <seed> <T>` |
| 8 | потенциал, ядро из суммы гауссиан | окружение `P_GS="a:σ,a:σ"`, `P_WIN`, `./fm 8 90 …` |
| 9 | **потенциал + окно из центроидов + цикл по своему тексель** (выбор ADR-054) | `./fm 9 90 <seed> <T> <Gn> <k> <ownExact>` |
| 10 | screened Poisson (Якоби) + окно | окружение `P_KAPPA P_ITERS P_WARM P_GAIN`, `./fm 10 90 <seed> <T> <Gn> <k> <ownExact>` |

Выбор ADR-054 (режим 9): `./fm 9 90 <seed> 15.1 180 2 1` (`Gn = 180` мелких ячеек по стороне, то есть 0,5 м; `k = 2` — окно 5×5; `ownExact = 1` — точный цикл по своему тексель).

Полный прогон до 15 с на `G = 180` занимает минуты. Для быстрой проверки берите `T = 5.1`.

Окружение для всех режимов: `M_FPS` (частота кадров, по умолчанию 60; `dt = 1/M_FPS`, поворот за шаг `turn·dt`), `M_UPD` (интервал обновления дальнего поля в кадрах, по умолчанию 1; поле строится на кадрах `s % M_UPD == 0`, частицы читают его каждый кадр; ближняя сетка режимов 5 и 9 строится каждый кадр). Метрики шума курса при разных `M_FPS` между собой не сравнивать: сравнивать с эталоном при том же `M_FPS`.

## 5. Запуск модели с капом (исходная)

```
./split dt mult cap seed T perTeam discR mode maxVisited capSep capAC
# опорный эталон без капа:  ./split 0.016667 4 0 <seed> 15 1500 12 0 | grep '^#f5'
# кап 48 (как сейчас):      ./split 0.016667 4 48 <seed> 15 1500 12 0 | grep '^#f5'
# раздельный кап (режим 4): ./split 0.016667 4 0 <seed> 5.1 1500 12 4 0 <capSep> <capAC> | grep '^#f5'
```
`capSep` и `capAC`: 0 — без капа для этого правила, иначе число посещённых слотов. Строки `#f5` содержат `contact`, `enemy`, `flocks` по метрикам ниже.

## 6. Метрики (общие у обеих моделей)

Расстояния периодические, радиус `R = 3`.
- `contact` — доля частиц, у которых есть хотя бы один чужой сосед в радиусе, %.
- `enemy` — доля чужих среди всех упорядоченных пар соседей в радиусе, %.
- `flocks` — число компонент связности графа «свой сосед в радиусе» размером не меньше 30, по командам.
- `pol` — среднее по частицам с хотя бы одним своим соседом: длина среднего курса своих соседей.
- `turn`, `turnSd` — среднее и стандартное отклонение модуля угла между курсом на шаге `s−1` и шаге `s`, рад (шаг 1/60 с).
- `vis`, `vis3`, `visMax` — число посещённых кандидатов на частицу: у ближнего цикла (среднее, максимум) и у обычного обхода 3×3 ячейки с `R` для сравнения.
- `rhoOwn50`, `rhoOwn90`, `rhoAll50` — плотность по конусу `h = 1,5` (на м²): медиана и 90-й процентиль своей команды, медиана всех.

## 8. Ограничения

- Одна геометрия: две команды, 3000 частиц, арена 90 м занята целиком, `R/c = 6`, `R/t = 3`.
- Контакт сильно разбросан по seed (ADR-052 даёт ±6 пунктов), различия в 1–2 пункта на пяти seed не значимы.
- Цена в операциях CPU и GPU-цены не связаны.
- Плотность равновесия (медиана own-плотности 19–41 на м²) у GPU-сцен P8.1 такая же, но на сценах S200 (729 м, спавн 0,49 на м²) не проверялась.
- В файлах нет самосилы-теста для нелинейных режимов (давление).
