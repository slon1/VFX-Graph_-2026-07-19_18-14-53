# ADR-001: Field resources (Milestone 2a) — архитектурные решения и их причины

**Статус:** принято (реализовано + правки по ревью, см. ТЗ `tz-m2a-review-fixes.md`)
**Дата:** 2026-07-26, дополнено 2026-07-28
**Область:** FieldSet / FieldDescriptor / FieldAccess / SimPass / SimulationWorld
**Связанные документы:** `architecture.md`, `status.md`,
план `.cursor/plans/milestone_2_field_resources_96b1c1f6.plan.md`

---

## Контекст

После Milestone 1 (частицы: ParticleSet + 17 пассов + touch) фреймворку нужны
grid-поля — без них недостижима половина целевых эффектов (Magic Fluids —
это 2D Stable Fluids на текстурах, не частицы). M2a — фундамент: ресурсная
модель полей + тонкий гибридный слайс (Touch → velocity field → частицы),
без самих Stable Fluids. Целевая платформа — мобильная (Android Vulkan /
iOS Metal), поэтому bandwidth и GC-аллокации в кадре — жёсткие ограничения.

## Решение 1 — Поля декларируются на EffectAsset, runtime их не создаёт (Policy C)

Пассы ссылаются на поля **по имени** и объявляют требования совместимости;
`SimulationWorld.Build` падает с внятной ошибкой, если поле не задекларировано.
Кнопка **Materialize missing fields** в инспекторе генерирует дефолтные
дескрипторы из запросов пассов.

**Почему:** формат/разрешение поля — контент-решение (параметр качества),
оно должно жить в ассете, а не выводиться магией из пассов. Автосоздание
маскирует опечатки в именах.

**Отклонено:** автосоздание полей из деклараций пассов (симметрично
авторегистрации атрибутов частиц). Асимметрия намеренная: атрибуты частиц —
дешёвые буферы с очевидными дефолтами, поля — дорогие текстуры с
контент-специфичными параметрами.

## Решение 2 — Три вида доступа: Read / WriteInPlace / WritePingPong

`FieldAccess` объявляется в `FieldRequest` пасса:

- `Read` — SRV, `SampleLevel`;
- `WriteInPlace` — RW-доступ к Current без swap (аддитивный splat: inject);
- `WritePingPong` — читает Current (SRV), пишет Next (UAV), после пасса — Swap.

**Почему:** исходная формулировка «write ⇒ ping-pong» неверна — swap после
аддитивного splat-а терял бы накопленное. Разделение делает семантику
машинно-проверяемой.

## Решение 3 — Swap принадлежит SimulationWorld, не пассам

World сканирует `FieldWrites` пасса при записи CommandBuffer и вызывает
`FieldSet.Swap` после каждого `WritePingPong`-пасса. Кернелы видят только
`{fieldName}Read` / `{fieldName}Write` и не знают о ping-pong.

**Дополнение (ревью):** swap выполняется только если пасс реально записал
dispatch (`SimPass.LastExecuteDispatched`) — иначе пасс с невалидным kernel
(добавлен в Play Mode без Rebuild) перещёлкивал Current на устаревшую текстуру.

**Почему:** DoD M2a — «ноль доменных веток в World». Swap, управляемый
декларациями, — data-driven шаг общего цикла, а не спецслучай.

## Решение 4 — Plane basis живёт в FieldDescriptor, не в InputRouter

Дескриптор несёт origin + axisU/axisV + size; кернелы сами проецируют
world-позиции на плоскость поля (`WorldToFieldUV`).

**Почему:** `InputRouter.CameraFacing` двигает интеракционную плоскость с
камерой — world-space поле к ней непривязываемо. Поле должно быть стабильным
в мире; InputRouter лишь настраивается на совместимый режим (GroundXZ в демо).

## Решение 5 — DecayField идёт через ping-pong намеренно

Decay — поточечная операция, ей ping-pong не нужен (можно in-place). Он
пущен через `WritePingPong` сознательно: это M2a-транспорт для сквозной
обкатки Swap-механики до появления advect (настоящей neighbor-reading
операции) в M2b. **Не «оптимизировать» без замены доказательства Swap.**

## Решение 6 — Раздельные FieldReads/FieldWrites, без унификации с частицами

`SimPass` получил два новых виртуальных списка с пустым дефолтом; `Reads`/
`Writes` частиц не тронуты, все пассы M1 не изменились.

**Отклонено:** единый `IReadOnlyList<ResourceRequest> Resources`. Унификация
отложена до M3+, когда третий тип ресурса (spatial hash) покажет реальную
форму абстракции.

## Решение 7 — Совместимость: semantic + каналы, формат/разрешение свободны

Пасс требует semantic + число каналов, не точный формат. Разрешение и
precision (R16↔R32) — «ручки качества» на EffectAsset.

**Уточнение (ревью 2026-07-28):** для **write**-доступа число каналов должно
совпадать **точно** (UAV layout обязан соответствовать объявлению kernel-а,
`RWTexture2D<float2>` + RGBA16F = UB на Vulkan); для **read** остаётся `>=`
(семплирование с отбрасыванием каналов легально). Precision по-прежнему
свободен.

## Решение 8 — Один FieldKernelPass = одна система координат поля

FieldParams (plane, resolution, texelSize) пушится единым блоком от
primary-поля. Валидация требует: одинаковый plane basis у всех полей пасса;
одинаковое resolution у всех **write**-полей (диспатч сайзится по primary).
Read-поля могут иметь другое разрешение — чтение идёт по нормализованному UV
(канонический сценарий M2b: dye выше разрешением, чем velocity).

**Отклонено (пока):** per-field uniform-блоки. Преждевременно до первого
настоящего multi-field пасса с несовпадающими полями.

## Решение 9 — Конвенции, влияющие на будущий код

- **Ноль аллокаций в кадре:** `FieldReads`/`FieldWrites` читаются World-ом
  каждый кадр ⇒ массивы `FieldRequest` кэшируются (`FieldRequestSets.Single`,
  `[NonSerialized]`-кэш, пересборка при смене имени). `new[] {...}` в свойстве —
  запрещённый паттерн.
- **Биндинг текстур:** `{fieldName}Read` (SRV) / `{fieldName}Write` (UAV);
  семплер `sampler_linear_clamp` — keyword-based inline sampler Unity
  (тот же механизм, что `sampler_LinearClamp` в SRP Core `GlobalSamplers.hlsl`);
  имя **корректно**, менять не нужно (проверено на ревью: заявление о паттерне
  `{filter}_{wrap}_sampler` — ошибочно).
- **Биндеры:** `VfxParticleBinder` биндит один раз в Initialize (буферы
  стабильны), `FieldQuadBinder` перебиндивает Current каждый кадр (swap меняет
  идентичность текстуры). Асимметрия ожидаема — не «чинить».
- **RenderTexture, не RTHandle:** RTHandle-система URP — для camera-scaled
  таргетов, полям она даёт только связанность.

## Последствия

- (+) Гибрид работает как обычный список пассов; World не знает о «fluid».
- (+) Новый полевой оп = kernel + класс `: FieldKernelPass` (2 файла по конвенции).
- (−) Асимметрия частицы/поля (авторегистрация vs декларации) — намеренная,
  пересматривается в M3+ вместе с унификацией ресурсов.
- (−) Multi-field пассы с разными плоскостями невозможны до введения
  per-field params — заблокировано валидацией, а не тихой ошибкой.
- Известный бэклог M2b: advect/Jacobi (Stable Fluids), ClampFieldPass или
  клэмп в inject, дропдаун имён полей в инспекторе пасса, обобщение
  FieldQuadBinder (сейчас жёстко «velocity»).
