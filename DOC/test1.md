# Техническое задание

## Проект

M3D Playground

## Цель

Создать минимальный Proof of Concept, демонстрирующий передачу данных между Compute Shader и VFX Graph через GraphicsBuffer.

Не проектировать архитектуру будущего продукта.

Не создавать абстракции.

Не делать систему операторов.

Главная задача — убедиться, что весь пайплайн работает.

---

# Стек

- Unity 6.4
- URP
- Visual Effect Graph 17.4
- UniTask
- C#
- HLSL Compute Shader

---

# Архитектурные ограничения

Использовать только:

- GraphicsBuffer
- Compute Shader
- VFX Graph

Все вычисления после инициализации должны происходить исключительно на GPU.

# Задача

Создать систему, которая:

1. Генерирует 1 000 000 частиц.
2. Загружает их в GraphicsBuffer.
3. Передает GraphicsBuffer в Compute Shader.
4. Каждый кадр вызывает Dispatch().
5. Передает тот же GraphicsBuffer в VFX Graph.
6. VFX Graph визуализирует частицы.

GraphicsBuffer должен быть общим.

Не создавать промежуточных копий.

---

# Структура данных

Использовать структуру

```hlsl
struct Particle
{
    float3 position;
    float value;
};
```

value пока не используется.

Он нужен как задел для следующих итераций.

---

# Размер буфера

Количество элементов:

```
1 000 000
```

Stride вычислять автоматически через Marshal.SizeOf.

Не использовать "магические числа".

---

# Генерация данных

При запуске приложения создать куб.

Размер:

```
100 ? 100 ? 100
```

Координаты распределить равномерно

```
[-1;1]
```

Буфер инициализируется один раз.

После создания CPU больше не изменяет позиции.

---

# Compute Shader

Создать один kernel.

Kernel должен выполняться каждый кадр.

Пока реализовать максимально простую операцию.

Например:

position.x += sin(position.y) * 0.001;

Главная цель —

визуально убедиться,

что Compute Shader действительно изменяет данные.

# VFX Graph

Создать Visual Effect Graph.

Использовать GraphicsBuffer как источник данных.

Каждая частица должна получать координаты

из GraphicsBuffer.

Индекс частицы должен соответствовать индексу элемента буфера.

Для чтения данных использовать Custom HLSL Block.

Не использовать встроенную симуляцию VFX Graph.

VFX Graph используется исключительно как Renderer.

---

# C# компонент

Создать MonoBehaviour

SimulationController

Он отвечает только за:

- создание GraphicsBuffer;
- генерацию данных;
- создание ComputeBuffer binding;
- Dispatch();
- передачу GraphicsBuffer в VFX Graph;
- освобождение ресурсов.

Не размещать вычислительную логику внутри MonoBehaviour.

---

# Inspector

Добавить параметры:

```
Particle Count

Cube Size

Simulation Speed
```

Даже если пока используется не всё.

---

# Освобождение ресурсов

Все GraphicsBuffer должны корректно освобождаться.

Использовать Release()/Dispose().

Не допускать утечек памяти.

---

# Код

Использовать SerializeField.

Не использовать Singleton.

Не использовать static.

Не использовать Regions.

Не использовать var там, где тип неочевиден.

Классы должны иметь одну ответственность.

---

# Критерии готовности

После запуска сцены:

? создаётся GraphicsBuffer на 1 000 000 элементов;

? Compute Shader успешно получает GraphicsBuffer;

? Dispatch() вызывается каждый кадр;

? VFX Graph читает тот же GraphicsBuffer;

? частицы отображаются на экране;

? изменение координат в Compute Shader сразу видно в VFX Graph;

? данные ни разу не копируются обратно на CPU.

---

# Важно

Проект является исследовательским прототипом.

Главная цель —

проверить работоспособность пайплайна

GraphicsBuffer > Compute Shader > VFX Graph.

Красота архитектуры сейчас не имеет значения.
